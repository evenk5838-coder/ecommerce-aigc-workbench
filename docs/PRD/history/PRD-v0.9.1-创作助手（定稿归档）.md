### 费用口径纠正（本版同步）

- `cost_cny` 是**应用侧估算**（单价 × 用量），**不得**称为「已核对的供应商账单」。
- 失败任务的 `cost_cny = null` 表示**未产生应用侧估算记录**，**不能**直接解释为「账单金额为零」；官方「仅成功生成计费」是规则说明，不等同于本项目已完成对账。
- 预算 `BUDGET_CNY` 与 `spent_today_cny` 均为本机估算闸门，不是服务商余额或发票口径。

## 1. 完成边界

### 1.1 目标闭环

```
选择模板/自由创作 → 准备商品素材 → 选择模型 → 确认参数与费用
   → 生成 → 原图对比 → 修改再生成 → 保存下载
```

### 1.2 纳入本版

| 项 | 说明 |
| --- | --- |
| 轻量商品信息 | 商品名/品类/需保留特征/禁用元素等字段，随任务与草稿持久化；不是完整商品库 |
| 原图对比 | 产物与原图并排人工对比，记录采纳/驳回与原因 |
| 输入与参数恢复 | 草稿与任务可恢复模板、字段、模型、参数、参考图 |
| 生成记录追溯 | 产物关联模型/模板版本/原图/参数/任务 |
| 模板入口 | 4 个首版模板 |
| 多模型选择 | 兼容过滤 + 切换保留可复用输入 |

### 1.3 暂缓

完整商品库、团队审批、复杂批次交付（按批次审核/命名/清单/自动交付包）、多 worker 并发、Webhook、无限节点画布。

### 1.4 保留

素材库、素材 ZIP 打包、固定尺寸排版、草稿、任务中心、单 worker 队列。

### 1.5 非目标

多步骤任务编排、自动抓取热点、文生视频、局部重绘/扩图、多 SKU 一致性保证、视频剪辑拼接、两个项目真实联通。

## 2. 主流程

| 步骤 | 行为 | 规则 |
| --- | --- | --- |
| 1 选模板/自由创作 | 模板列表或直接创作 | 浏览模板**不产生费用** |
| 2 准备商品素材 | 上传/选择商品图，填字段 | 上传只创建素材，不产生费用 |
| 3 选择模型 | 从兼容模型中选 | 未开通置灰；EOS 模型标注下线时间 |
| 4 确认参数与费用 | 展示**最终生效参数**与费用估算 | **必须**调 `POST /api/tasks/estimate`（无副作用）；确认后才调 `POST /api/tasks` |
| 5 生成 | 提交→排队→轮询 | 提交即付费 |
| 6 原图对比 | 并排对比 | 人工判断，记录采纳/驳回；自动一致性校验未实现 |
| 7 修改再生成 | 复用输入与参数 | 重试即重新生成、再次计费；保留历史版本 |
| 8 保存下载 | 入素材库/导出 | 可追溯模型、模板版本、原图、参数 |

## 3. 失败与修改流程

| 场景 | 错误码 | 行为 |
| --- | --- | --- |
| 参数校验失败 | `VALIDATION_FAILED` | 提交前拦截，不计费 |
| 模板字段缺失/非法 | `TEMPLATE_FIELD_REQUIRED` / `TEMPLATE_FIELD_INVALID` | 提交前拦截 |
| 模板不存在/版本不存在 | `TEMPLATE_NOT_FOUND` / `TEMPLATE_VERSION_NOT_FOUND` | 404 |
| 模板与模型不兼容 | `MODEL_TEMPLATE_INCOMPATIBLE` | 400，给出可用模型列表 |
| 模型未开通 | `MODEL_NOT_OPENED` | 前端置灰；已提交则提示去控制台开通（**实测不计费**） |
| 预算不足 | `BUDGET_NOT_APPROVED` / `BUDGET_EXCEEDED` | 402，不发起付费请求 |
| 生成失败 | `failed` | 显示错误码与下一步 |
| 创建结果不明 | `CREATE_RESULT_UNKNOWN` | 禁止直接重试，先人工对账 |
| 一致性不通过 | — | 记录驳回原因→修改再生成；不改写历史任务 |
| 云端运行中取消 | — | 明确"云端可能仍在执行并计费" |
| 草稿冲突 | `DRAFT_VERSION_CONFLICT` | 停止覆盖，另存新草稿 |
| 模型已到 EOS | `MODEL_EOS` | 新任务不可选，提示迁移目标；历史任务照常可查 |

### 13.1 边界：直接操作完整保留

### 13.2 三种交付形态（v0.9 新增，回应"仅优化也应是完整交付"）

### 13.4 复用哪些现有接口（不新增平行系统）

| 助手动作 | 复用接口 | 说明 |
| --- | --- | --- |
| 能力/可用性 | `GET /api/models` | `activation` + `lifecycle`（含 EOS） |
| 模板推荐 | `GET /api/templates`、`GET /api/templates/{id}?version=` | 只推荐真实存在的 `template_id` |
| 素材 | `GET /api/assets`、`POST /api/assets` | 首版只用**元数据**，不读取图片内容 |
| 报价 | `POST /api/tasks/estimate` | **唯一**报价来源；返回 `effective` + `estimated_cost_cny` |
| 提交 | `POST /api/tasks` | 仅在有**服务端批准**时调用 |
| 状态 | `GET /api/tasks/{id}`、`POST /api/tasks/{id}/cancel` | 沿用现有取消语义 |
| 重试 | `POST /api/tasks/{id}/retry` | 助手路径需用户触发；**手动接口行为不变** |

| **用户确认** | **需新增**（见 §13.9 G8） | 现有接口没有"用户批准"语义 |

### 13.5 报价与确认：两个独立动作（v0.9 新增）

| 概念 | 含义 | 不能证明什么 |
| --- | --- | --- |
| **报价单**（estimate 结果） | 系统算过这次方案的费用与生效参数 | ❌ 不能证明用户同意执行 |
| **服务端批准** | 用户在界面上显式确认后，服务端记录的一条批准 | ❌ 不能跨方案复用 |

规则：

1. 报价先形成**待确认方案**；界面向用户展示模板/模型/`effective`/估算费用（标注"估算，非账单"）。
2. 用户确认必须由**界面操作**触发，由后端记录：批准绑定**方案哈希 + 会话/项目 + 有效期 + 一次性使用**。
3. `submit` 只凭**批准**，不凭报价；报价单直接提交 → 409。
4. **参数变更**（模板、模型、比例、尺寸、时长、提示词主体）→ 旧批准失效，**重新报价 + 重新确认**。
5. **重复提交不重复生成**：批准一次性 + 幂等键，重复请求返回同一任务。
6. **来源由后端确定**：助手执行器写入 `origin=assistant` 与会话 ID，不信任模型传入的 `caller_id`；
   不能通过把 `caller_id` 改成 `local` 绕过确认。
7. 手动路径（`origin=manual`）**不需要**批准，行为与现在完全一致。

### 13.6 约束分层：提示词 vs 后端强制

| 约束 | 写入提示词 | 必须后端执行 |
| --- | --- | --- |
| 仅优化模式不进入生成 | ✅ 意图判断 | ✅ 无批准不得提交（后端不解析意图，只看批准） |
| 不虚构商品事实、不承诺质量 | ✅ 主要手段 | ⚠️ 仅能抽检，需人工复核 |
| 提问/轮次上限 | ✅ | ✅ 助手专属配置，不影响手动接口 |
| 报价 ≠ 确认 | ✅ | ✅ 报价记录与批准状态分离 |
| 确认绑定本次方案 | ✅ | ✅ 方案哈希 + 有效期 + 一次性 |
| 重复提交幂等 | ✅ | ✅ 批准 + 幂等键 |
| 助手来源可信 | — | ✅ 后端写入，不信任模型传参 |
| 价格只来自 estimate | ✅ | ✅ |
| 模型可用性/EOS/参数能力 | ✅ | ✅ 复用现有错误码 |
| 内容安全（涉黄/暴/政、违规电商宣传） | ✅ 前置劝阻 | ✅ 供应商审核为权威 + 记录 `CONTENT_REJECTED` |
| 额度/成本 | ✅ 提示 | ✅ 助手与生成**分别计量**；账本未实现 |

> **纪律**：提示词是行为引导，不是安全边界。"写了提示词所以安全"不成立。

### 13.7 商品事实、内容范围与能力边界（v0.9 修订）

- **首版无视觉能力**：助手看不到图片内容。商品名称、数量、包装、材质、功效等只能来自**用户文本**或用户确认过的资料。
- **禁止推断**：不得从文件名、素材尺寸、素材 ID、来源渠道推断商品品类、数量或外观。
- **缺失处理**：模式 A 用占位符并列出待补充项；模式 B 停在「待补充」，可用"创意默认值"但须标注待确认。
- **质量承诺**：不得承诺画质、审核通过、上架成功、销量；可说明已知限制。
- **内容范围**：拒绝涉黄、涉暴、涉政与违法违规创作；拒绝医疗功效宣称、绝对化用语、虚假对比等误导性电商宣传；拒绝时给合规替代方向。
- **启用看图需单独变更**：届时须说明图片发往哪家模型服务，并把"模型识别结果"与"用户确认事实"分开呈现。

### 13.9 本轮识别出的缺失能力（不开发，仅登记）

| # | 缺失能力 | 为什么必须有 |
| --- | --- | --- |
| G1 | 后端 LLM 代理接口（厂商无关适配层） | Key 不能放前端；需统一限流与审计 |
| G2 | 工具执行器（薄封装现有函数） | 复用现有能力，不重写任务系统 |
| G3 | **用户确认/批准接口** | `estimate` 是报价，不能替代用户同意 |
| G4 | 批准校验（方案哈希 + 有效期 + 一次性 + 幂等） | 防"报价即提交"、防参数漂移、防重复生成 |

| G6 | 助手专属限流（提问/轮次/工具/费用） | 防无限聊天与成本失控；不波及手动路径 |
| G7 | 助手用量记录（与生成用量分开） | 后续统一积分换算的前提 |
| G8 | brief 正式存储（暂用草稿） | 跨会话稳定延续 |
