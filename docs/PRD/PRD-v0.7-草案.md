## 2. 主流程

### 2.1 入口

- **自由创作**：延续现有"生图/生视频"两入口。
- **模板创作（新增）**：模板列表 → 看效果示例与适用条件 → 填写页。

### 2.2 步骤定义

| 步骤 | 行为 | 规则 |
| --- | --- | --- |
| 1 选模板/自由创作 | 选模板或直接自由创作 | 模板页只展示元信息与示例，**不产生费用** |
| 2 准备商品素材 | 上传/选择商品图；填写轻量商品信息 | 上传只创建素材，不产生费用 |
| 3 选择模型 | 从兼容模型中选 | 未开通置灰；切换保留可复用输入，标记不兼容参数 |
| 4 确认参数与费用 | 展示本次任务明细与费用估算 | 确认后才提交；后端二次校验预算 |
| 5 生成 | 提交 → 单 worker 排队 → 轮询状态 | 提交即发生付费调用 |
| 6 原图对比 | 产物与原图并排对比 | 人工判断；记录采纳/驳回与原因；**自动一致性校验未实现** |
| 7 修改再生成 | 复用原输入与参数，修改后新建任务 | 重试即重新生成（再次计费）；保留历史版本 |
| 8 保存下载 | 产物入素材库，可导出 | 关联模型/模板版本/原图/参数/任务，可追溯 |

## 3. 失败与修改流程

| 场景 | 触发 | 行为 |
| --- | --- | --- |
| 参数校验失败 | 必填缺失、参考图非图片/超大、比例非法 | 提交前拦截，4xx + 明确 code，不产生费用 |
| 模型未开通 | `MODEL_NOT_OPENED` | 前端置灰；已提交则提示核对开通 |
| 预算不足 | `BUDGET_NOT_APPROVED` / `BUDGET_EXCEEDED` | 402 提示；不发起付费请求 |
| 生成失败 | `failed` | 显示错误码 + 可执行下一步 |
| 创建结果不明 | `CREATE_RESULT_UNKNOWN` | 隐藏直接重试，先人工对账（可能已计费） |
| 一致性不通过 | 人工对比发现数量/主体不符 | 记录驳回原因 → 修改再生成；不改写历史任务 |
| 云端运行中取消 | 本地停止等待 | 明确"云端可能仍在执行并计费" |
| 草稿冲突 | 版本不一致 | 停止自动覆盖，提供"另存新草稿" |
| **模型下线（迁移期）** | 模型进入 EOS 后调用失败 | 提示该模型已下线 → 引导选用已验收的替代模型；不自动切换、不复用旧参数强投 |

**一致性边界**：本版只做人工对比 + 提示词预设（不增删商品、不写图中没有的商品）。数量/主体自动校验仍属后续能力。

**代码口径待修正（本轮不改代码，登记于此）**：`backend/app/config.py` 的 `IMAGE_PRICE_CNY` 对 pro 记为固定 `0.30`，未区分像素档。历史任务未使用 pro，因此**已有费用记录未受影响**；该口径应在契约更新阶段改为按像素档计价。

## 6. Seedance 1.0 Pro Fast 迁移计划【拟议·待确认】

4. **模型记录保留**：下线后该模型在模型目录中标记 `deprecated`/`eos`，历史任务详情仍能显示当时使用的模型与版本。

## 7. 单次创作模板【候选·未接通】

> 四模板均为【候选】。首版人工维护，不自动抓热点，不升级为多步骤编排。稳定 `template_id`（语义 ID）+ 整数 `template_version`。

### 7.1 通用结构与版本规则

```
template_id       语义稳定标识（如 tpl_white_bg）
template_version  递增整数（1,2,3…）
category          work（工作模板）| hot（热点/主题模板）
kind              image | video
name/description  名称与说明
effect_sample     效果示例（真实样例；暂无则置空，不硬编假图）
required_assets   必填素材
fields_json       填写字段 schema
default_params    默认生成参数
compatible_models 兼容模型约束
status            active | deprecated | eos
```

**版本可追溯（硬规则，【拟议·待确认】）**：
- 模板**发布后不可原地修改**；任何字段/默认参数/兼容模型变更 → 新建 `template_version`。
- 每个版本的完整内容快照存入 `template_versions`，**永久保留**。
- 任务落库时写入 `template_id + template_version`；历史任务详情按该版本快照展示当时内容，**不随模板升版而变化**。
- 模板下线（`deprecated`/`eos`）只影响新任务可选性，不影响历史任务追溯。

### 7.2 四个候选模板

#### T1 商品白底背景（work · image）

| 项 | 内容 |

> 定位【已确认】：运营工作台**尚未开发**；首版**只做接口契约 + 本机测试调用方验证**，不做真实联通、不做完整团队额度系统、不做 Webhook。

### 8.1 契约增量（复用现有接口，只增不改）【拟议·待确认】

| 能力 | 接口 | 增量 |
| --- | --- | --- |
| 能力发现 | `GET /api/models` | 扩展 `input_modes`/`ratios`/`resolutions`/`duration_s`/`pricing`/`params_schema` |
| 模板发现 | `GET /api/templates`、`GET /api/templates/{id}`（含版本） | 新增 |
| 素材输入 | `POST /api/assets` | 已有；跨项目按 asset_id 引用，**不传本机绝对路径** |

| 版本兼容 | `/v1` 前缀或 Accept 版本头 | 预留；字段只增不改 |

### 8.2 "鉴权预留"与"已实现鉴权"的区别（必须区分）

| 维度 | 当前实况 | "鉴权预留"含义 | 什么才算"已实现鉴权" |
| --- | --- | --- | --- |
| 是否存在鉴权 | **不存在**。所有接口无身份校验，仅靠 127.0.0.1 与 CORS 白名单限制来源 | 契约中预留 `X-API-Key` 头、`caller_id` 字段与错误码定义 | 服务端校验凭据、拒绝无效请求、有越权负向测试 |
| 调用方身份 | 无 `caller_id` 概念 | 任务表预留 `caller_id` 字段 | 每个任务与用量可归因到具体调用方 |
| 数据隔离 | 无用户维度；`assets.owner` 默认 `local` | 设计文档说明未来按 owner 隔离 | A 用户无法读取 B 用户素材/任务/草稿，并有负向测试 |
| 额度/计费 | 仅本机单一预算闸门 `BUDGET_CNY` | 预留计量字段 | 按调用方预占/结算/对账 |
| 对外安全性 | **不可对外接入** | — | 通过上述全部后另行声明 |

**表述纪律【已确认遵守】**：本版任何文档、汇报、验收记录**不得**写"已可对外安全接入"、"已鉴权"、"两项目已联通"；只能写"鉴权字段已预留（未实现校验）"、"本机测试调用方已验证契约"。

### 8.3 测试调用方验证（本机脚本，不宣称联通）

验证序列：上传/引用素材 → 提交任务（带 `external_request_id` + `client_request_id`）→ 轮询状态 → 下载结果文件 → 用同一 `client_request_id` 重复提交（应返回已有任务而非新建）。

### 8.4 明确不做

- 不建立两项目共享数据库；不把本机路径当远程素材地址；不把预留字段算作已完成集成；不做外部调用方真实接入。
