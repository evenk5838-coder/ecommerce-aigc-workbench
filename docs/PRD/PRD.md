## 1. 用户、任务和交付

面向需要制作电商图片与短视频的创作者。产品继续提供两类入口：

- **快捷工作台**：目标明确时直接生成单素材，明确区分文生图、图生图、文生视频、图生视频。
- **导演台**：通过连续对话和自由画布，把想法、脚本、参考素材逐步变成分镜图、镜头视频和成片；也支持从已有素材中途开始。

用户提供创作诉求、真实商品信息和可用素材，提出修改建议并确认本次动作。系统负责整理需求、生成实际内容、保存到项目、显示真实执行结果并引导下一步。

交付包括可编辑文本／脚本、图片、独立视频片段、完整成片及既有下载／导出能力。节点配置、素材引用、用户确认、任务及历史产物必须持久化。手工节点与 Agent 操作指向同一份业务数据。

## 2. 相对 v0.10 的变化与优先级

本稿是完整产品基线上的增量说明；未修改的已确认能力继续有效。以下对应条款已获确认并取代旧表述，不把旧版“当时现状”继续当作当前状态。

| 旧表述／问题 | v0.11 要求 |
| --- | --- |
| 固定八阶段节点、画布只展示流程 | 全工作区自由画布，可自主创建文本、图片生成、视频生成节点和导入素材 |
| 项目级阶段门槛，必须从需求一路补齐 | 按目标动作的真实输入依赖判断；已有图可做视频，已有视频可直接合成 |
| 对话只澄清和写草案，确认后解锁手动按钮 | 对话可调实际工具；用户确认当前动作后执行，不到隐藏表单再点一次 |
| 节点主要从已有脚本／镜头状态派生 | 节点具有独立身份、配置版本、输入、任务和选中产物；自动创建和手动创建一致 |
| 左边固定表单／聊天，右边局部画布 | 主要工作区是画布，对话可收起；删除重复标题和占地项目条 |
| 后端由 Pi、前端由 Codex 分别承接 | 当前 Codex 统筹前后端、接口、集成与验收；可内部并行分工 |
| 旧文档仍有“只支持 5/10 秒”“没有项目／镜头表”“按分镜时长裁切”等过时或冲突句 | 规格以当前能力和账号状态为准；承认已有业务底座；继续纯拼接、不裁剪 |

优先级：先完成**自由节点基础与真实对话脚本闭环**，再接通对话中的图片和视频生成，最后完成两种交付模式及完整恢复验收。不能把第一批完成写成整版已完成。

## 3. 对话创作过程

### 3.1 专业职责

| 职责 | 沟通内容 | 必须交付的实际结果 |
| --- | --- | --- |
| AI 编剧 | 创作目的、商品事实、表达风格、必要约束 | 可阅读、可编辑、已保存的脚本及对应文本节点 |
| AI 导演 | 已选脚本、镜头方案、画面风格、参考素材与图片设置 | 镜头方案及按确认范围生成的逐镜图片节点 |
| AI 摄影师 | 动作、运镜、时长、视频规格和输出方式 | 真实镜头视频及逐镜状态 |
| AI 剪辑师／自动合成 | 参与片段、顺序和交付方式 | 可播放、可下载的成片 |

职责随当前任务衔接，保留已知需求、素材和版本，不让用户重复自我介绍或切换多个会话。职责名称不规定独立 Agent 数量。

### 3.2 正常路径

1. 用户提出想法。系统只问影响结果的缺失信息；已有信息不重问，不虚构商品事实。
2. 用户明确要求起稿，或澄清完成并确认起稿后，系统实际生成、保存脚本并关联文本节点。已有明确起稿指令不重复确认。失败必须说明真实错误或可恢复卡点，不能留下“稍等”却没有任务继续执行。
3. 用户在对话或节点中修改脚本，一次确认保存当前编辑并确认对应版本，无需分开“保存”和“确认”。
4. 导演提出镜头方案；沟通画面、参考图与必要参数后，展示本次图片生成的目标和费用信息。用户确认当前范围后直接建立节点、任务并执行。
5. 图片逐镜出现。用户可直接设置单节点，也可说“只把第二张改成近景”；只调整目标内容，其余成功素材保留。
6. 用户审核图片并与摄影师沟通视频需求。确认本次视频动作、规格、输入与费用后执行。
7. 选择“完整视频”时，本次明确范围可包含全部镜头成功后的自动合成；不再强制切换剪辑师重复确认相同计划。选择“独立分镜视频”则先交付片段，需要时再确认合成清单。

### 3.3 中途开始和直接操作

允许直接编辑／导入脚本、上传或引用图片、导入已有视频。系统依据当前可用输入决定目标动作；缺什么补什么，不强制补齐无关阶段。用户关闭对话仍能在节点上直接创作。

导入图片后可选择图生图或图生视频；文本输入可选择文生图或文生视频；已有视频可选择合成。是否可执行仍受当前模型能力、引用可读性和确认范围约束。

## 4. 画布与节点

### 4.1 空间和显示

- 保留 C 版顶部导航、黑白底色／蓝色强调和深浅主题。主导航下方以画布为主，不再给画布单独一小块区域。
- 删除“项目名／创作项目”独立大条及重复标题；项目名仅在一个紧凑位置展示，保留返回导演台项目列表的入口。
- 对话可收起，收起不丢消息、输入草稿和在途操作。具体停靠形式见第 10 节建议。
- 支持自由拖动节点、平移／缩放画布、适配全图及布局恢复。
- 支持手型平移与箭头选择，空白处拖动框选多个节点、成组移动和批量删除；单个节点选中后同样可删除。
- 单／批量误删均可撤销，提供撤销入口及画布 Ctrl／⌘+Z；恢复节点内容、位置、参数和引用关系，保留原素材和任务，不触发重新生成。撤销不能覆盖其他节点后续编辑；输入框内快捷键优先用于文字撤销。删除记录持久化，重开可恢复；身份／版本冲突明确提示。
- 初始只展示实际内容；后续节点随创建和执行出现，不预铺未来空表单。用户主动新建空节点不受限制。
- **设置区随所属节点移动，并随画布同比缩放**。输入控件操作不能误触拖动；必要时通过聚焦／适配视图方便操作。
- 默认界面展示用户能理解的进度和结果，不显示 taskId、数据库版本、服务端校验说明等开发字段。
- 项目首页介绍快捷工作台与导演台的区别，不铺四种生成模式入口卡；四模式在实际创作入口明确呈现。删除指定首页句子“目标明确时，快速生成素材；需要梳理想法时，与 AI 一起完成创作。”
- 不恢复独立版本历史大面板、“每次保存会新增版本”等说明；历史数据继续保留，可按需查看。快捷生成底部主要保留生成按钮，删除“上传／编辑不收费”“今日估算／非实际账单”等指定说明；实际生成前的必要报价与预算校验仍保留，积分展示后续再议。

### 4.2 独立内容和设置

| 节点 | 内容与适用操作 |
| --- | --- |
| 文本／脚本 | 真实正文、手工编辑、Agent 修改；脚本与镜头关联，不能只有聊天预览 |
| 图片生成 | 文字或图片输入、模型、提示词、参考图和适用规格；显示真实图片及生成状态 |
| 视频生成 | 文字／首帧等模型实际支持的输入，独立模型、提示词、时长、比例、清晰度等设置；可播放结果 |
| 导入素材 | 图片／视频的持久化引用，可作为其他节点输入或合成来源 |
| 成片结果 | 已选片段及明确顺序、计划／实际时长、播放和下载 |

参数按模型和模式显示，只允许兼容组合。比例用“横版 16:9／竖版 9:16／方形 1:1”等易懂表达，清晰度单独表达，不堆长像素数字。

节点的身份、坐标、正文、生成配置、素材版本和任务关系都需恢复。不能只保存布局，刷新却丢提示词和参考图。布局改变不等于生成输入改变，拖动节点不影响成片顺序。

## 5. 确认、费用、版本和异常

### 5.1 当前动作只确认一次

确认绑定具体动作、节点／镜头、输入版本、规格、数量、输出方式和必要费用信息。对话里无歧义的确认与按钮确认进入同一执行逻辑。涉及多个候选动作时先明确指向，不能把一句含糊确认扩大成后续全部付费授权。

保存脚本、批准图片和批准视频是不同范围；确认脚本不自动付费生成媒体。完整视频一次批准可覆盖明示的镜头任务和成功后自动合成。输入／规格／数量／价格或范围发生变化时，更新受影响的待确认内容。

预算校验继续在服务端执行。费用不能由模型自由猜测；区分估算、预留和真实已记录用量，不伪造积分体系。此前授权范围保持其原边界，未自动扩大为新测试或新供应商授权。

### 5.2 成功与恢复

对话结束、任务受理和产物就绪分别判断。写脚本成功需要真实保存及节点关联；媒体成功需要真实任务结果、可读／可解码文件和持久化关联。排队、运行、供应商失败、输出无效、取消和提交结果未知分别反馈。

刷新、离开再返回或服务重启后，已保存的项目、节点、确认、任务和产物可查回。在途任务按原任务／供应商 ID 续查；不能为恢复而重新生成。没有远端 ID、受理结果不明时保留待核对，不承诺自动续跑或自动重发。

失败修复有明确边界：参数校验错误可有限纠正；模型输出截断或无效结构要识别；达到尝试／预算上限给出真实失败。不能无界搜索、改提示词后静默重试或重复扣费。

### 5.3 局部修改和两种交付

- 只修改第二镜时保留第一镜和旧第二镜的成功产物；旧版与新版可追溯。
- 上游替换后标记受影响下游，不删除旧结果，不静默重做或扣费。运行中任务继续归属于提交时的输入版本。
- 重排只影响合成顺序，不使镜头素材失效。合成使用明确的片段列表和选定版本。
- 完整视频存在失败镜头时不伪称完整；给出定向重试或用户明确选择的部分合成。
- 先保留模型合法原生时长与顺序纯拼接，不做裁剪、变速、补帧、补时长。计划时长与产物实测时长分别展示。

## 6. 既有功能保留清单

本轮为增量改造，以下不重新列为全新功能，也不能在重构中丢失：

1. 快捷工作台、四种输入方式、单次模板、主动润色、参考素材复用。
2. 项目首页与导演台项目列表、创建／打开／删除、正确返回、不自动弹抽屉、失效项目处理及首页滚动。
3. C 版深浅主题、节点拖动和平移缩放、已实现的保存＋确认合并。
4. 素材上传、预览、真实视频播放、下载、既有排版／PNG／ZIP 导出。
5. 手工脚本编辑、历史脚本和成功素材、片段和成片版本。
6. **结构模板保存／查看／套用入口随隐藏面板删除一起迁移**；不复制商品事实，每次重绑素材和校验模型，已套用项目不自动跟随模板升级。
7. 模型支持／账号开通／平台验证分开；前端、校验、报价、实际请求规格一致，不静默改值。
8. 后端预算、确认范围、请求回执、防重复提交、局部失败和未知结果恢复。

## 7. 质量、数据及交付约束

### 7.1 什么算生成得好

脚本应符合用户诉求和已知商品事实，能读、能改、有可执行镜头建议；图片应对应镜头内容并保留商品主体与已确认限制；视频应使用选定输入及规格，不能用静态占位冒充真实视频；成片应对应已选镜头和顺序，能够实际播放下载。

生成任务完成并不代表主观质量通过。首次真实样例验证分别记录事实准确、需求覆盖、修改定位、商品／风格一致性、视频动作及成片感受，由用户查看评分；数值标准待真实样例形成，不虚构通过率或时延指标。

### 7.2 模型、成本和数据

继续沿用已有已配置、已开通的文本／图片／视频服务和预算机制，不因参考 Pixelle 新增服务商或 GPU 部署。具体适配、已验证范围与真实测试用例在下一阶段核对；未验证模型不能按参考代码的能力标记宣称可用。

继续本地工作台的部署形态，不在本次迭代里新增公开发布、多租户或云平台迁移。用户素材、草稿和历史不因测试或更新被清理；敏感配置沿用现有服务端管理，不进入前端或交付证据。上传仍执行真实类型、格式、大小等校验。

### 7.3 本轮非目标

不纳入：复杂时间线裁切、自动补帧／变速、强制旁白／字幕／配乐、数字人、动作迁移、模板市场、通用条件／循环工作流、多 Agent 团队、公开部署和新增多用户系统。专业子 Agent 是否有价值后续用真实任务比较，不按竞品角色数量决定。

## 8. 开发组织与阶段交付

推荐在当前对话统筹，不要求用户另建对话。开发协作的多个工作流与产品内部 Agent 架构分别管理。

先修订技术／前端适配与接口约定；再按一个最小用户任务做“前端＋后端＋真实模型”的纵向切片，逐条扩展。工程可按不同文件并行，阶段验收统一；按用户最新模型切换要求，先做后端，前端开始前明确提醒并等其切好模型，不一次铺开所有功能。

| 分工 | 工作边界 |
| --- | --- |
| 主控／集成 | 维护唯一 PRD 与接口基线，拆任务，处理公共文件／迁移／合并，组织真实验收与状态记录 |
| 前端实现 | C 版画布空间、对话、自由节点、设置、导入、确认及结果反馈；按正式前端标准验证桌面与窄屏 |
| 后端实现 | 脚本与 Agent 工具、节点业务持久化、输入依赖、确认执行、真实任务与恢复、版本及范围校验 |
| 检查／验收 | 契约一致性、保留能力、错误／恢复、真实产物、用户可操作路径；不能只以 mock 或构建通过宣布完成 |

公共类型、路由、数据迁移和接口文档由主控协调；先确定输入／输出／错误，再分配不同文件的实现。各工作流不自行重启或更改正式服务、不并发写业务数据库、不自行追加付费测试；需要时由主控按授权统一执行。

| 切片 | 目标 | 必验内容 |
| --- | --- | --- |
| 0 PRD 与适配 | 本稿评审、缺口关闭、技术和前端适配／接口增量 | 用户任务、边界、保留项、分工与费用约束一致 |
| 1 自由节点与真实脚本 | 大画布、节点创建／导入、配置恢复、对话写出脚本并定位节点；迁移模板入口 | 实际保存脚本；无隐藏按钮依赖；设置随缩放；刷新后节点／正文／配置一致 |
| 2 图片与视频 | 对话方案、范围确认、独立参数、真实媒体任务、局部修改与恢复 | 逐镜真实产物；只重做目标；受理未知不重发；成功项保留 |
| 3 成片 | 完整／独立片段两模式、显式顺序、导入视频继续、下载／导出 | 完整路径及中途开始均通过；纯拼接；真实播放；计划与实际时长分开 |

保留到正式产品的最小界面从第一切片起按正式前端标准检查，不另造一套用完即弃的产品。每切片交阶段文档、实际检查输出、用户可操作清单和证据，真实验证未完成时明确标“待验，未完成”。

## 9. 验收清单与 41 条需求追踪

### 9.1 关键验收场景

| 编号 | 输入与操作 | 通过条件 |

## 10. 已确认实施方向与代表页待验项

用户已明确的功能要求不再重复征询。以下实施方向随本稿获确认；具体视觉宽度、引用控件和版本呈现继续通过代表页验收：

- 推荐一个主控 Agent 按任务加载专业能力，复用现有模型与执行服务，不引入固定四 Agent 团队。
- 推荐可收起的停靠／浮动对话，画布延伸到面板下方；宽度和位置通过代表页评审。
- 推荐素材引用能看见来源与版本；使用连线或选择器的具体呈现由原型确定，不增加通用循环编排。
- 推荐重做保留历史、默认选中新结果；新节点派生或节点内版本的默认呈现通过原型确定。
- 推荐当前对话统筹前后端；先对齐契约，再按切片联调与验收。用户后续要求进入前端或后端前提前说明，便于切换模型；当前先后端，前端须提醒并等用户切好模型。

本稿已确认，按切片修订技术／前端适配、工具／接口契约及阶段任务。当前先做后端；进入前端前提醒用户并等待其切换模型。新增付费验收在具体用例、报价和原授权余额核对后单独处理，不把对本稿的确认解释为无限付费授权。
