## 0. 一条主线：**不新增第二套执行系统**

```
引导创作空间（新 UI + 新实体）
        │  只做"编排 + 展示 + 确认"
        ▼
现有 tasks / batches / worker / estimate / assets / templates / assistant
```

**所有真实生成仍然只有一个执行单元：`tasks` 表 + 单 worker 队列。**
分镜图 = 图片任务；镜头视频 = 视频任务（首帧=分镜图）；成片 = 本地 ffmpeg 拼接（不是模型任务）。

这样做的理由（对应 starter-kit「最小改动」原则）：
1. 任务、取消、重试、重启续查、预算闸门、费用口径**全部复用**，不产生第二套语义；
2. 引导空间只增加"项目/脚本/镜头/分镜/成片/结构模板"这些**组织层**实体；
3. 出问题时可退回现有工作台，产品不会因为新入口而整体不可用。

## 2. 数据模型（新增表，全部 additive）

> 迁移方式沿用 `db.MIGRATIONS`（`CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ADD COLUMN`），**不重建库、不改旧表语义**。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `projects` | `id, name, brief_json, status, structure_template_id, structure_template_version, created_at, updated_at` | 项目根；`brief_json` 存商品事实与禁用元素 |
| `script_versions` | `id, project_id, version, content_json, source(assistant\|manual\|template), session_id, confirmed_at, created_at` | **只追加不覆盖**；`UNIQUE(project_id, version)` |
| `shots` | `id, project_id, script_version_id, seq, duration_s, description, motion, status, approved_at` | `duration_s` 为**模型原生区间内整数秒**；无裁切字段 |
| `storyboards` | `id, shot_id, asset_id, version, status(draft\|approved\|rejected), reject_reason, created_at` | 一镜多版本，取 approved |
| `shot_takes` | `id, shot_id, task_id, asset_id, spec_json, duration_ms, cost_cny, status, created_at` | 每次生成一条；**不删旧 take** |
| `films` | `id, project_id, version, items_json, duration_ms, asset_id, status, created_at` | `items_json` 记录有序 take 列表 + 各自实际时长 |
| `generation_scopes` | `id, project_id, mode(full\|clips), shot_ids_json, specs_json, scope_hash, estimated_cost_cny, expires_at, approved_at, status` | **整组确认凭证**（见 §4） |
| `structure_templates` | `id, name, latest_version, status, created_at` | 与 `templates`（单次）**分开** |
| `structure_template_versions` | `id, template_id, version, snapshot_json, created_at` | `snapshot_json`：镜头职能/顺序/节奏/运镜/原生时长；**不含商品事实** |
| `projects_ops`（审计，可选） | `id, project_id, op, payload_json, created_at` | 记录确认、重排、重试等操作 |

**状态机（镜头）**

```
draft → storyboard_pending → storyboard_approved
      → queued → running → succeeded
                        ↘ failed（可定向重试）
```

**成片**

```
pending → composing → ready | partial(缺镜，需显式确认) | failed
```

## 4. 生成范围（scope）与"一次确认"

沿用助手已验证的"报价≠批准"模式，抽到创作空间：

```
POST /api/projects/{id}/scope
  → 逐镜 estimate（复用 cloud_tasks.estimate_cost）
  → 返回 { scope_id, mode, shots:[{shot_id,duration_s,estimate}], total_estimate, scope_hash, expires_at }

用户点「生成完整视频 / 生成分镜视频」
  → POST /api/scopes/{id}/confirm  → { approval: scope_id 已批准, 有效期 600s, 一次性 }

提交
  → POST /api/projects/{id}/generate { scope_id }
  → db.transaction: 校验 scope 未过期/未使用/哈希一致 → 建 batch → 逐镜建 task（多镜头）
```

**失效规则（修订：不再有"只提示旧分镜"的例外）**

`scope_hash` 覆盖**每镜完整输入快照**，任一变化即失效，必须重新报价 + 重新确认：

| 变化 | 效果 |
| --- | --- |
| 镜头集合（增删）/ 顺序 | `scope_hash` 变化 → 旧 scope 失效 |
| 每镜时长 / 规格（模型、比例、清晰度）/ 模式 | 失效 |
| **镜头描述（description）** | **失效**（描述进入该镜提示词） |
| **最终提示词（prompt）** | **失效** |
| **参考图 / 首帧素材（input_asset_id）** | **失效** |
| **已批准分镜版本（storyboard version）** | **失效** |
| scope 过期（>600s） | 409，需重新创建 |
| 重复提交同一 scope | 幂等：返回原 batch |

**冻结内容（每镜一份 `frozen_input`）**
```
{ shot_id, seq, description, prompt, input_asset_id, storyboard_id, storyboard_version,
  model_id, ratio, resolution, duration_s }
```
- 提交时按 `frozen_input` 执行，**不重新读取当前镜头状态**；
- **旧结果归原版本**：scope 变更后新提交产生新 take/新 film 版本，旧 take/旧成片保留并标注所属版本；
- 不允许"沿用旧确认去生成新内容"（否则等于用旧价格买新内容）。

**"一键"的真实含义**：提交时**一次创建 N 个任务**进同一 batch；
执行仍由**单 worker 顺序**消费——**不是并行**，UI 必须如实展示"排队中"，不得显示"同时生成中"。

## 4.1 对象版本与并发规则（S3/S4 前置设计，S1 不实现）

| 对象 | 版本策略 | 并发写规则 |
| --- | --- | --- |
| `script_versions` | 只追加，不覆盖 | 并发编辑 → 各自新增版本；冲突以 `base_version` 校验，不匹配 409 |
| `shots` | 每镜有 `revision`（自增） | `PATCH` 必须带 `expected_revision`；不匹配 409 `SHOT_REVISION_CONFLICT` |
| `storyboards` | 每镜多版本（`version` 自增） | approve 绑定 `storyboard_id+version`；新版本不继承旧批准 |
| `generation_scopes` | 一次性；`scope_hash` 绑定冻结输入 | 批准后禁止修改；消费后不可复用 |
| `shot_takes` | 每次生成新增一条 | 不覆盖，不删除；重试 = 新 take |
| `films` | `version` 自增 | 新合成 = 新版本；旧版本保留 |

**时钟与过期**：scope 批准有效期 600s，服务端时间判定，过期即 409。

## 4.2 提交事务设计（S3/S4 前置设计，S1 不实现）

一次 `POST /api/projects/{id}/generate` 必须在**单个 SQLite 事务**内完成：

```
BEGIN IMMEDIATE
  1) 读 scope：存在 / 已批准 / 未过期 / 未消费 / scope_hash 与冻结输入一致
  2) 消费 scope（条件更新 approved→consumed，rowcount=1 才继续）
  3) INSERT batches（1 行）
  4) INSERT tasks（N 行，shot_id 写入 client_request_id 派生键）
  5) INSERT shot_takes（N 行，status=queued，task_id 关联）
  6) INSERT submit_receipts（1 行：scope_id + batch_id + task_ids + 冻结输入哈希）
COMMIT
```

- **任何一步失败 → 整组回滚**（不产生半个 batch、不残留已消费的 scope）；
- **重复提交**：先按 `scope_id` 查 `submit_receipts`，命中则**直接返回原 batch**，不进入事务，不重复建任务；
- 幂等键：`scope_id`（一 scope 一 batch）；task 级仍保留 `client_request_id` 兼容旧机制；
- `submit_receipts` 是"提交收据"，用于对账与重复提交判定，**不可变**。

## 5. 时长校验改造（B10）

| 层 | 改造后行为 |
| --- | --- |
| 元数据 | `duration_range_s=[2,12]`、`duration_step_s=1`（1.0 pro fast）；其余模型按官方能力 |
| 前端 | 只渲染 `min..max` 按 step 递进的整数秒；切换模型重建选项；未开通模型禁用 |
| 后端 | `validate_params_for_model`：类型必须 `int`（拒绝 `5.5`）、`min ≤ d ≤ max`、`(d-min) % step == 0`；否则 400 `MODEL_CAPABILITY_MISMATCH` |
| 报价 | 用校验后的同一 `duration` 计算 token 估算 |
| 供应商请求 | `video_create(duration=d)` 用同一值 |
| 历史 | 不改写旧任务/旧报价；旧记录按其原始参数与费用口径展示 |

**明确禁止**：`round()`、`int()` 截断、静默改值、`min(max(d,min),max)` 夹取。非法输入一律报错。

## 6. 成片拼接（`assembly.py`）

| 项 | 设计 |
| --- | --- |
| 输入 | 有序 take 列表（`asset_id` + `duration_ms`）+ 目标顺序 |
| 处理 | `ffmpeg -f concat -safe 0 -i list.txt -c copy`；若片段编码不一致 → 回退统一转码后 concat |
| **裁剪** | **不做**（Q3）：不裁入点/出点、不变速、不补帧 |
| 缺镜 | 提交前检测；缺镜时**不产出"完整视频"**，返回 `partial` 状态 + 缺失镜头列表 |
| 实际时长 | 用 ffprobe 探测每条片段，成片时长＝**实测之和**；与"计划时长"分字段返回 |
| 失败 | 具体片段损坏 → 指出 shot_id；已生成片段保留；可只重合成 |
| 费用 | 无模型调用；平台是否对合成收费未定（配置项预留 `ASSEMBLY_FEE_CNY=0`，**默认 0 且不对外承诺**） |
| 版本 | 每次合成产生新 `film.version`，旧版本保留 |

**模式1 vs 模式2**
- 模式1：整组成功后**自动调用** assembly，产出 film；
- 模式2：不自动调用；用户点"合成成片"时调用（若之前已有 film，则生成新版本）。

## 9. 错误与异常（新增错误码）

| code | HTTP | 含义 |
| --- | --- | --- |
| `SCOPE_REQUIRED` | 409 | 未提供范围确认就提交 |
| `SCOPE_EXPIRED` | 409 | 范围确认过期 |
| `SCOPE_STALE` | 409 | 镜头集合/规格/模式已变，需重新报价确认 |
| `SCOPE_ALREADY_USED` | 409 | 该范围已提交过（重复提交按幂等返回原 batch） |
| `SHOT_NOT_READY` | 409 | 镜头缺分镜图或未审核通过 |
| `FILM_MISSING_SHOTS` | 409 | 成片缺镜（返回缺失 shot_ids） |
| `ASSEMBLY_FAILED` | 502 | 拼接失败（返回涉事 shot_id） |
| `STRUCTURE_TEMPLATE_VERSION_NOT_FOUND` | 404 | 模板版本不存在 |
| `DURATION_NOT_SUPPORTED` | 400 | 时长不在模型原生区间内（含小数秒） |

> 复用既有：`MODEL_CAPABILITY_MISMATCH`、`MODEL_EOS`、`MODEL_NOT_OPENED`、`BUDGET_*`、`TASK_*`。

## 12. 风险与取舍

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 单 worker 下"整组生成"耗时长 | 5 镜 × 30–60s ≈ 数分钟 | UI 如实显示排队/逐镜进度；不承诺并行；后续再议并发 |
| ffmpeg 编码不一致 | 不同片段参数可能不同 | `-c copy` 失败即回退统一转码；记录回退原因 |
| 时长改动影响历史 | 旧任务按 5/10 记录 | **不重解释历史**；新任务才用新区间 |
| 画布成本 | 无限画布易膨胀 | 只做固定节点 + 平移缩放；不做连线编辑器 |
| scope 与分镜图不一致 | 用户改了分镜图但沿用旧 scope | 提交时提示"基于旧分镜"；建议重新报价 |
| 结构模板被当作"效果保证" | 商业表达风险 | 文档与 UI 明确：只提供结构，不保证效果 |
