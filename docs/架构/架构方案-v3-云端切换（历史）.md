# 架构方案 v3 · 本地工作台 + 火山方舟云端推理

> 2026-10-22 15:55｜对应 PRD v0.5｜v2（全本地）已归档为历史
> 变更方式：**在现有代码上替换推理供给方**，不重建项目、不删数据。

## 1. 变更摘要（一句话）

把 `engines.py` 里的"本地 diffusers 推理"换成"云端 Ark 调用"，其余（任务队列、素材库、草稿、错误结构、状态机、预览接口）**原样保留**；视频新增"异步任务 + remote_task_id 持久化 + 轮询 + 结果下载"链路。

```
改动前： worker → engines(本地 MPS) → 磁盘
改动后： worker → cloud_tasks(Ark HTTP) → 磁盘（素材库同一套内容寻址）
                         ↳ remote_task_id / usage / cost 落 SQLite
```

## 2. 组件对照

| 层 | v2（本地，历史） | **v3（当前）** |
| --- | --- | --- |

| 任务状态 | queued→loading→running→… | 新增 `remote_queued / remote_running`；终态不变 |

| 计费 | 无 | 预算闸门 + `cost_cny` + `/api/usage` |
| 密钥 | 无 | `.env` → `ARK_API_KEY`（进程内读取，不外泄） |

## 4. 关键实现约束（逐条对应你的要求）

| 要求 | 实现 |
| --- | --- |
| 云端任务 ID 立即持久化 | `video_create` 成功 → `db.update(remote_task_id, status=remote_queued)` 就在同一函数内，先写库再轮询 |
| 重启后继续查询 | `reconcile()` 把带 `remote_task_id` 的非终态任务重置为 `queued(stage=resume_poll)`；`run_video` 见 `remote_task_id` 已存在则**跳过创建**直接轮询 |
| 创建超时不盲目重发 | `providers_ark.video_create` 捕获网络类失败 → 抛 `CREATE_RESULT_UNKNOWN`；worker 记为失败（不重试）；`safety_identifier=本地 task_id` 供对账 |
| 取消不夸大 | 排队中：真 DELETE；运行中：返回 `{result:"cancel_requested", cloud_canceled:false, message:"…云端可能仍在执行并计费"}` |
| 结果落本地 | 下载 → `storage.save_bytes(..., source="cloud_generated")` → 复用 `/api/assets/{id}/file` 预览 |
| 用量/耗时/错误 | `usage_json`、`cost_cny`、`latency_ms`、`task_attempts`、`api` 错误码入库 |
| 不把模拟当真实 | 无 Key 时任务直接 `AUTH_MISSING`；`fake-image` 仍仅测试环境注册 |

## 5. 预算闸门

```python
spent_today = SUM(cost_cny) WHERE finished_at > 今日0点
if APP_BUDGET_CNY <= 0        → BUDGET_NOT_APPROVED（不发起请求）
if spent_today + 本次估算 > 上限 → BUDGET_EXCEEDED
```
估算：图片按张单价；视频按 `token/秒 × 时长 × 单价`（系数来自官方示例，实测后校准）。
