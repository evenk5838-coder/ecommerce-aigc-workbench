# 架构方案 v5（v0.7 增量：模板 / 多模型能力 / 计价校准 / 跨项目预留）

> 2026-10-23｜对应 PRD v0.7｜v4（云端图生图）已归档 `docs/架构/架构方案-v4-云端图生图（历史）.md`
> 原则：**不重建、不另起任务系统**。模板是「参数+提示词+校验」的配置层，不是独立执行引擎；
> 不引入编排器、不引入新供应商、不改前端。

## v5.0 本轮改动面（只碰这些）

| 层 | 文件 | 改动 |
| --- | --- | --- |

| 数据 | `backend/app/db.py` | 新增 `templates` / `template_versions`；`tasks` 增 5 列 + 2 索引 |
| 模板域 | `backend/app/templates.py`（新增） | 4 模板种子、字段校验、提示词组装、版本快照 |
| 接口 | `backend/app/main.py` | `/api/models` 扩能力；`/api/templates` 新增；`POST /api/tasks` 支持模板与外部关联 |

**不动**：worker 调度与单 worker 语义、队列、草稿、素材库、预算闸门逻辑、`frontend/` 全部代码。

## v5.1 分层位置（模板不新增执行层）

```
交互层   前端（本轮不改）
产品层   模板列表/字段表单/生成确认（前端后续实现）
编排层   —— 无。模板不是编排器，单次任务仍是 1 task = 1 次模型调用 ——
能力层   templates.resolve_for_task()：校验 → 组装提示词 → 返回默认参数
模型层   providers_ark：image_generate / video_create / video_query
数据层   tasks / template_versions / assets
```

**为什么不做模板执行引擎**：PRD 明确「单次创作模板，不是多步骤任务编排」。引入节点/编排会增加失败面而不增价值。

## v5.2 任务创建时的解析顺序（已实现）

```
1) client_request_id 命中 → 直接返回原任务（幂等，不新建）
2) 模型存在性 + kind 匹配
3) 若有 template_id → templates.resolve_for_task()
     a. 取 template_versions 快照（默认最新 active 版本）
     b. 字段校验（必填/下拉/自定义/必填素材/概念图必填商品名）
     c. 组装提示词（预设 + 字段，概念图路径追加声明）
     d. 模板默认参数只补缺，不覆盖请求显式值
     e. 模板↔模型兼容性校验（kind + input_modes 交集）
4) kind=image → generation_mode 校验；kind=video → 必须有首帧 asset
5) 入库（含 template_id/version、external_request_id、caller_id、concept_mode）
```

## v5.3 计价架构（单入口）

```
config.image_cost_cny(model, size, ref_count)   # 单一价 or 像素档 + 参考图加价
config.video_cost_cny(model, params)            # token 公式 × 单价
        ↓
cloud_tasks.estimate_cost()  → budget_gate()  → 提交前响应 estimated_cost_cny
        ↓
任务成功后：视频用 usage.completion_tokens 重算，覆盖估算（图片按张）
```

关键事实：官方 token 公式 `(输入+输出时长)×宽×高×帧率/1024` 已用本项目实测 103,818 tokens 反算验证。

## v5.4 生命周期与迁移

`MODEL_LIFECYCLE` 驱动 `/api/models.lifecycle`：`active` / `eos_scheduled`。
官方公告已明确「生图生视频模型不会自动迁移到新模型」→ 架构上**不实现自动切换**，只做：
EOS 后从新任务可选列表移除 + 提示迁移目标 + 历史任务照常可查。

## v5.5 安全边界（本版未变，勿误读）

- 无鉴权、无用户隔离、无额度体系；`caller_id` 仅落库不校验。
- 不对外暴露服务；仅 127.0.0.1 + CORS 白名单。
- 供应商 Key 只在后端进程内使用，不下发前端或调用方。

# 架构方案 v4（增量迭代：云端图生图 + 生成方式字段）

> 2026-10-22｜对应 PRD v0.6｜v3（云端切换）已归档 `docs/架构/架构方案-v3-云端切换（历史）.md`
> 原则：**不重建、不另起任务系统**，在现有 `POST /api/tasks` 上补齐 `generation_mode` 与参考图传递。

## 1. 本轮改动面（只碰这些）

| 层 | 文件 | 改动 |
| --- | --- | --- |
| 接口校验 | `backend/app/main.py` | 任务/批量提交增加生成方式校验矩阵 |
| 云端执行 | `backend/app/cloud_tasks.py` | `run_image` 支持参考图，读取本地素材并按官方方式传入 |
| 素材 | `backend/app/storage.py` | 新增 `asset_data_url()`：按真实 MIME 生成 `data:` URL |
| 配置 | `backend/app/config.py` | 视频单价修正 15.0 → **4.20**（官方核实） |
| 错误 | `backend/app/errors.py` | 新增参考图相关错误码 |
| 契约 | `docs/接口/接口契约.md`、`docs/接口/交接-Codex.md` | 示例、默认值、兼容规则、错误、批量/重试 |

**不动**：任务表结构（`input_asset_id` 已存在）、队列、worker 分派、草稿、素材库、预算闸门、前端。

## 2. 接口面（兼容增量）

```jsonc
// 文生图（旧请求，行为不变）
{ "kind":"image", "model_id":"doubao-seedream-5-0-flash-260915",
  "params": { "prompt":"…", "size":"1024x1024" } }

// 图生图（新增）
{ "kind":"image", "model_id":"doubao-seedream-5-0-flash-260915",
  "input_asset_id":"asset_…",
  "params": { "generation_mode":"image_to_image", "prompt":"保持商品不变，背景改为大理石台面", "size":"1024x1024" } }
```

**兼容规则**：`generation_mode` 缺省 = `text_to_image`；此时即使带 `input_asset_id` 也不传参考图（保持旧行为，避免旧调用突然变成付费图生图）。

### 2.1 校验矩阵（提交时拦截，不产生费用）

| generation_mode | input_asset_id | 结果 |
| --- | --- | --- |
| 缺省 / `text_to_image` | 无 | ✅ 文生图 |
| 缺省 / `text_to_image` | 有 | ✅ 文生图（**忽略**参考图，并在任务 `params` 回显 `ignored_reference:true` 便于前端提示） |
| `image_to_image` | 无 | ❌ 400 `REFERENCE_IMAGE_REQUIRED` |
| `image_to_image` | 有，但素材不存在 | ❌ 404 `ASSET_NOT_FOUND` |
| `image_to_image` | 有，但 `kind != image` | ❌ 400 `ASSET_NOT_IMAGE` |
| `image_to_image` | 有，但文件缺失/不可解码 | ❌ 400 `INVALID_REFERENCE_IMAGE` |
| 非法枚举值 | — | ❌ 400 `VALIDATION_FAILED`（附允许值） |
| 视频任务 | — | 走原有首帧逻辑（不受本字段影响） |

**禁止**：图生图失败时静默退回纯文生图；换模型替代。

## 3. 图生图数据流

```mermaid
flowchart LR
  U[上传参考图] --> A[assets 表 + 本地文件]
  A --> T[POST /api/tasks<br/>generation_mode=image_to_image]
  T --> Q[队列 queued]
  Q --> W[worker → cloud_tasks.run_image]
  W --> V{校验：asset 存在/是图片/可解码}
  V -->|通过| B[storage.asset_data_url → data:image/jpeg;base64,…]
  B --> R[providers_ark.image_generate(image=…)]
  R --> D[base64/url → 本地落盘]
  D --> S[assets 登记 + 任务 usage/cost]
```

关键点：

1. **执行层真的传图**：`run_image` 内读取 `input_asset_id` 对应文件，转 data URL 传给 `image` 字段；不是只把 ID 存进数据库。
2. **MIME 用真实的**：从 `assets.mime` 取（`image/jpeg` / `image/png` / `image/webp`），不再一律当 PNG。
3. 参考图格式：官方示例使用 URL；本地素材改为 **data URL（base64）**，**以真实调用验证**是否被接受，结果写进契约（若被拒则回退方案见 §7）。

## 4. 批量与重试的隔离

| 场景 | 机制 |
| --- | --- |
| 批量 | 每个 item 独立 `TaskIn` → 独立 `tasks` 行（各自 `input_asset_id` + `params` 快照）；`batch_id` 仅分组 |
| 重试 | `retry` 复制原任务的 `input_asset_id` 与 `params`；可用 `params` 覆盖（如换提示词），**但不会继承别的任务的参考图** |
| 并发 | 单 worker；`input_asset_id` 是任务行字段，不共享全局变量 → 结构性防串图 |

## 5. 结果与记录

沿用现有：`storage.save_bytes(..., source="cloud_generated")` → `assets` 登记（sha256/尺寸/MIME）→ `/api/assets/{id}/file` 预览；任务记录 `latency_ms`、`usage_json`、`cost_cny`、`remote_task_id`（视频）。

## 6. 费用口径修正

| 项 | 旧 | 新（官方核实） |
| --- | --- | --- |
| `doubao-seedance-1-0-pro-fast-251015` | 15.00 元/百万 token（保守估算） | **4.20 元/百万 token**（不含输入视频，官方价格页） |
| 图片 flash | 0.12 元/张 | 不变 |

- 历史任务行的 `cost_cny` **不重算、不篡改**，在评测报告注明"旧口径按 15.0 估算，实际约 3.6 倍高估"。
- 新任务按下表价格计算，仍标注为**估算**（不等于账单）。

## 7. 风险与回退

| 风险 | 处理 |
| --- | --- |
| Ark `image` 不接受 data URL | 真实调用验证；被拒则记录错误并提方案（见契约"待定"），**不擅自换模型、不静默降级** |
| 大图 base64 过长（>10MB） | 上传上限 20MB；执行前校验 base64 长度，超限报 `INVALID_REFERENCE_IMAGE` 并提示压缩 |
| 参考图不被模型"尊重" | 属模型效果问题，单独评价（PRD §7 V2 分别评价"生成成功"与"商品一致"） |

## 8. 验证计划（先模拟，后真实）

| 类型 | 内容 | 结论边界 |
| --- | --- | --- |
| 模拟（pytest/脚本） | 校验矩阵 6 例；参考图是否进入请求体（mock 抓 body）；批量两任务不同参考图不串；重试保留参考图 | 只证明调用链与错误处理 |
| 真实冒烟 | 1 次图生图（¥0.12）：清晰商品图 → "保持主体，改背景" | 证明云端链路；效果需人工评价 |
| 回归 | 1 次文生图（¥0.12）确认旧行为不变 | 同上 |

预算：本轮真实调用计划 **≤ ¥0.5**（在既有 ¥20 预算内，不提高上限）。

## 9. 不做（本轮）

- 无限节点画布（数据结构/执行引擎/连线交互）→ 后续阶段，文档不得写成已实现。
- 白底/氛围/自定义三套后端流程 → 只做提示词预设。
- SKU 一致性保证 → 未实现，不承诺。
- 前端页面改造 → Codex。
