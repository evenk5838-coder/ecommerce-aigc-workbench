## 导演台与真实契约的对齐

导演台读取服务端返回的可见步骤、当前脚本与确认状态。前端不会将历史 `confirmed_at` 等同于当前需求及脚本仍有效，也不会自行推导业务确认链。服务端确认链仍有缺口，因此当前页面状态不能证明制作链路已完成验收。

本轮同时修正了分镜审核路径及确认参数、镜头创建回执、嵌套片段状态、成片实际时长、导出下载地址、结构模板回执与幂等提交回执等契约误配。读取失败或请求结果未知时保留输入和已返回的编号，先核对状态，不自动重发可能产生费用的请求。

镜头目前由后端保存的字段为描述、时长和运镜；分镜生成用的提示词与参考图仍属于当前浏览器输入，不能宣称已具备跨设备恢复。成片实际时长缺失时显示未知，不以计划时长代填；版本总数也不作为完整历史列表展示。

详细问题、静态证据和后端验收要求见：[前端—后端待补：四种生成方式与渐进导演台](../接口/前端-后端待补-四模式与导演台-20261026.md)。该交接的后端静态核对基准为主仓 `4a1b8b7`，不代表其后修复已被验证。

## 后续必须闭合的缺口

1. **B0：文生视频。** 后端允许合法纯文字视频请求，并统一模式、参考图与重试语义；完成复核后才解除前端提交禁用。
2. **B1–B3：导演确认链与动作。** 镜头修改、分镜重生成或驳回应使旧确认及报价失效；各写接口执行同样的前置校验；合成、导出动作与实际产出状态一致。
3. **B4–B6：制作数据完整性。** 补齐结构模板列表、可核实的分镜及片段历史、活动任务恢复和镜头模型上下文等契约，避免前端用猜测补齐。
4. **统一验收。** 后端交付后先进行隔离联调，再按批准范围进行真实模型及恢复验证，最后完成浏览器和人工验收。真实调用不由此文档自动授权。
