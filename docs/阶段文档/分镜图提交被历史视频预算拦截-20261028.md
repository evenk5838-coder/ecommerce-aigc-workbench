后续反馈（2026-10-28）：用户明确表示画布功能及完整链路已全部试过且可用，本问题的用户复验完成。以下保留修复时的诊断、验证和当时状态。

## 用户反馈

用户在生成分镜图步骤看到：`模型 doubao-seedance-2-0-260128 的时长不合法：got=5（not_integer）`。

## 已核实原因

- 正式业务库中存在一条该模型的旧视频任务，状态为 `failed`，错误码为 `CREATE_RESULT_UNKNOWN`，没有远端任务 ID 或已结算费用。
- 该任务保存的 duration 为整数 `5`，并非字符串或小数。
- 分镜图组提交会先调用 `node_execution._budget_in_tx`，核算历史未确定任务的费用预留；该旧任务因此被纳入。
- 此模型仍在登记表和价格表，但没有时长能力配置。`resolve_duration_s(..., strict=False)` 返回空，`video_cost_cny` 把所有解析失败统一错误标为 `not_integer`，导致与当前分镜图无关的旧视频校验阻断提交。

只读复现使用 SQLite `mode=ro`，禁止网络连接并拦截后续预算入口，直接执行 `_budget_in_tx(connection, 0.12)`；复现完全相同错误，detail 为 `policy.kind=unavailable, reason=not_integer, got=5, got_type=int`。调用栈：`node_execution.py:198 → cloud_tasks.py:24 → config.py:465`。没有调用模型、提交任务或改写业务数据。

## 修复范围与验收要求

1. 区分历史任务费用预留和新视频请求的模型能力校验；保留结果未知任务的费用预留，不以删除记录、忽略未知费用或按零元处理来解除阻塞。
2. 优先复用可信的已冻结估价；旧记录无冻结估价时，制定独立且可核验的历史估价策略。无法可靠估价时返回可理解的历史预算状态错误。
3. 错误信息区分缺少模型能力、类型非法和时长越界；不把配置缺失误报为用户输入错误。
4. 隔离回归覆盖：历史未知视频 + 新分镜图提交、确实非法时长、超预算拦截、远端成功但本地下载失败仍预留、结算后不重复预留、重复确认不重复建任务。
5. 免费隔离验证通过后再更新本地服务；本次未批准新的付费调用。用户已明确回复“已切好后端模型，修复这个问题”。

这是用户前端检查中新发现的后端缺陷；此前的真实模型隔离验收未覆盖此条历史业务数据组合，不能用此前通过结果覆盖本问题。

## 本次实现

- 关联画布执行的已消费报价优先用于费用预留，校验报价哈希及任务输入一致；报价失效时间不影响已提交任务的费用预留。
- 报价之前的旧视频记录，按保存的整数时长、已知尺寸档和登记价格计算预留，不依赖当前提交能力；历史 `5.0`／`"5"` 只做无损兼容，不填默认时长、不截断小数。
- 缺少可靠数据或报价损坏时返回 `BUDGET_RESERVATION_UNAVAILABLE` 并携带任务 ID，供核对；不会自动按零元处理。
- 新视频请求仍走严格时长策略；错误原因区分配置缺失、非整数、越界和步长。
- 新增同类旧任务 + 导演两张分镜提交／幂等／超预算回归；扩展免费 HTTP 验收，可携带同类旧视频跑通脚本→分镜→视频→成片并重启复验旧记录原样保留。
