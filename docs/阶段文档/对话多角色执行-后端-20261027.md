## 1. 本批做了什么

| 能力 | 当前实现 |
| --- | --- |
| 一个会话、多种职责 | 新主控承担 writer／director／cinematographer／editor；依据真实项目和选中节点推导角色，不需要四套独立对话 |
| 对话直接写脚本 | 需求足够调用 write_script；普通“稍等”有一次修复机会，仍未行动则明确失败；有缺项通过结构化 clarify 返回 |
| 真实脚本节点 | 脚本、canonical `script` 节点、提案、确认动作、工具回执同事务；保存后确定性回执，不再多调一次模型包装成功 |
| 现有脚本可恢复确认 | `prepare_script_confirmation` 为当前脚本准备缺失／过期入口；不新建脚本版本，不替用户确认；旧版本拒绝 |
| 分镜图片节点 | 当前脚本确认后或从自由文本创建逐镜 image 节点、保存合法参数和真实镜头来源；自动准备该组报价，尚不入队 |
| 视频节点 | 从指定成功图片输出或导入图片冻结引用，创建 video 节点；无脚本也能中途进入 |
| 单镜修改 | 对指定 text/image/video 做局部修改并校验 revision；只报价修改的媒体节点，保留其他镜头 |
| 一次确认整组生成 | 用户确认冻结 action 后，全部节点／引用／费用校验通过才原子入队；重复确认重放，无自动重试付费任务 |
| 视频与成片一次批准 | output_mode=film 时，一次确认仅覆盖本组视频生成与按明确 node_ids／sources 顺序完整拼接；全部本次视频成功且素材可用后自动合成，不再调用模型或二次确认 |
| 独立成片合成 | 有序视频来源、明确合成确认、持久化本地队列、真实 FFmpeg、可读成片素材节点；不按画布位置猜剪辑顺序 |
| 产物实际可用性 | 节点执行与成片读取校验记录、文件可读性和 SHA-256；task succeeded 不等于文件可用，缺失或同尺寸替换不会被显示为成功产物 |
| 回执与旧接口 | 新 conversation/state/request/action 入口；旧 chat 保留；失败和部分成功可读，pending GET 不重跑模型 |
| 启动中断恢复 | 仅在新流程请求 owner 明确结束时保存 failed／partial 回执；保留产物、动作、任务、原始消息和未知费用；存活／未知 owner 及旧流程不抢占 |

新增主要模块为 `director_creation.py`、`director_workflow.py`、`director_generation.py`、`director_composition.py`、`director_recovery.py`，并接入路由、主进程和已有节点执行／确认事务能力。新工作记录使用 `director_tool_operations`、`director_actions`、`director_compositions`，不迁移或清理用户已有项目／素材。

## 2. 用户注释与实现对应

- “确认诉求后直接写，不要藏在手动资料里”：后端新对话不要求 intent 或隐藏生成脚本按钮；实际 UI 移除旧入口和切换 API 留给下一批前端。
- “写完要自动出脚本文本框”：保存回执带稳定 node_id 和脚本版本绑定，前端可定位真实节点。
- “导演给出逐镜图片，每张能调”：后端保存独立 image 节点，每节点有完整配置和 revision；图片执行结果来自真实任务。
- “下一步摄影师用这些图生成视频”：视频引用固定到明确的成功图片／导入素材，不以脚本是否存在阻断中途进入；可选择逐条素材，或一次批准本组视频与按明确顺序拼接，全部视频可用后自动产出成片。
- “我已经有视频，可直接继续”：独立合成接受明确来源和顺序，不要求重新补脚本和分镜。
- “只改某个镜头”：节点更新不覆盖其他镜头，生成方案只包含被修改节点。
- “不要再只有一句稍等”：结果必须有已保存产物／动作，或明确澄清／讨论；未执行和部分失败独立返回。

全屏画布、C 版主题、节点设置随画布缩放、项目入口／删除、节点拖动与快捷工作台区分等已在前序前端需求中保留；本批后端文档不把它们重复计为新完成项。

## 5. 启动恢复与实际产物状态

`director_recovery` 已接入服务启动，并有 15 项隔离回归。新请求持久化原消息、session、选择和 owner PID／启动时间。仅 PID 已不存在或可靠启动时间戳证明 PID 被复用，才将该请求从 pending 改为 failed，并保存 `DIRECTOR_REQUEST_INTERRUPTED`；已有产物或动作时 outcome 为 partial。工具产物、actions 和已受理媒体任务保留，原始用户消息恢复到历史，`usage.has_unknown_cost=true`，不把未知费用写成零。

启动时间通过 `ps` 在 `TZ=UTC`、`LC_ALL=C` 下读取，并使用 `utc-lstart-v1:` 前缀；只有同版本时间戳可比较，避免时区、语言环境或旧格式差异导致误判。存活进程、权限不足或缺少 owner 证据的请求、旧流程请求不会被另一服务抢占。回收只解除已结束对话自身的 pending 保护，其他运行任务仍会阻止不安全的项目删除。GET 始终只读，超时不自动重发，也不调用模型补跑。

节点 execution 新增 `asset_available`、`asset_error`、`result_status`，文件 SHA-256 实际校验可识别同尺寸内容替换。generation 按本次 execution 的成功状态及实际产物可用性聚合，不用旧成功版本充当本次结果；成片读取也验证文件完整性。film 分别给出 `media_status` 与整体 `status`，只有最终成片可用才 completed；缺失镜头阻止自动拼接，合成失败保留成功镜头并返回 error，不自动改成残缺成片。

本地合成队列有独立持久化结果与中断状态；生成远端任务继续沿用原任务恢复边界。三者不得用同一“重新生成”按钮不加区分地重跑。

## 6. 前端交接与下一步验收

下一批前端开发开始前需明确告知用户，方便切换模型。接入范围如下：

1. 正式导演对话改用 `/director/conversation`，传稳定请求号、选中节点和当前工作流修订；角色标签依服务端状态变化。
2. 聊天中展示脚本／生成／合成 action 卡；明确 clips／film、镜头顺序和批准范围；film 一次确认视频与完整拼接，不再增加第二次合成确认，不从模型文字推断批准，不重复增加隐藏生成按钮。
3. 从 artifacts 和 actions 的真实 ID 定位画布，刷新脚本／图片／视频节点；节点设置中的未保存草稿、revision 冲突和旧成功结果保留。
4. 异步任务读动作／execution 状态及 asset_available；film 区分 media_status 与成片整体状态，最终素材从 composition 读取。unknown/pending 只读恢复，明确中断展示保留产物；局部失败保留成功内容，恢复不得重复付费入队。
5. 导入图片直接转视频、导入视频直接合成；合成顺序由用户确认，不依赖节点位置；仍明确四种生成输入方式。
6. 在 C 版深浅主题及宽／窄窗口做实际浏览器走查，再安排真实模型的最小收费验收；固定替身证据不能替代自然语言、脚本质量、图片连贯性、视频运动和完整成片观看。

目前 film 自动成片范围已实现为“本次批准的视频生成 + 按明确顺序完整拼接”；clips 独立交付和已有视频单独 compose 继续保留。跨图片与视频阶段的一次无限批准、替换为后来生成的成功版本、失败自动付费重试，以及配乐／字幕／转场／剪裁／自动选片不在当前能力内，界面不能据此扩展授权。
