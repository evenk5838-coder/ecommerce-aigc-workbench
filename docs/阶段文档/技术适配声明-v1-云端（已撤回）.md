# 技术适配声明

> 版本：v1（2026-10-22）｜对应 PRD v0.3｜项目：电商 AIGC 工作平台
> 依据：`ai-product-starter-kit` 阶段 1 固定格式；本声明供你确认三件事（见我最后一段）。

## 1. 产品形态判断

- **形态**：单机本地 Web 工作台（后端 + 最小验收页）+ 云端模型推理（火山方舟）。
- **开发路径**：**纵向切片**（手册允许的路径 B）。理由：本产品的价值必须「用眼睛看、亲手点」才能判断（图片/视频是否为可用素材、任务状态是否可信），仅靠 API JSON 无法验收；因此本阶段同时交付「最小后端 + 最小验收页 + 真实一次图片/一次视频」。
- **明确不采用**：路径 A「后端先行、界面留到最后」。因为验收对象包含画布类交互与产物预览，纯后端无法判断质量。

## 2. 采用的默认方案

| 层 | 方案 | 理由 |
| --- | --- | --- |
| 后端语言 | Python 3.12（独立 venv；本机现装 3.9.6 不满足默认基线） | 手册默认；与生态（httpx/pydantic）一致 |
| 后端框架 | FastAPI + Uvicorn | 手册默认；自带 OpenAPI，便于交接 Codex |
| 数据校验 | Pydantic v2 | 手册默认；接口与外部响应双重校验 |
| 持久化 | **SQLite + SQLAlchemy + Alembic** | 本次触发条件：多实体（asset/task/batch/draft）+ 状态机 + 并发修改 + 重启恢复 |
| 文件存储 | 本地目录 `data/assets/`（内容寻址） | 大二进制不进关系库 |
| 任务执行 | **进程内持久化队列**（SQLite 任务表 + 单 worker 线程 + 租约） | 单用户单机，规模未达引入 Redis/Celery 的阈值；手册明确「达规模阈值后」才引入队列 |
| 长任务交互 | 「提交 + 轮询查询」为主；SSE 仅用于任务列表事件推送（可选） | 手册：只需后台执行可不用 SSE；若用 SSE 必须以 done/error 收尾 |
| 测试 | pytest（mock 云端 + 失败注入） | 手册默认 |
| 前端（本阶段） | 单 HTML 最小验收页，FastAPI 静态挂载，原生 JS + fetch | 手册 §五「用于验收的最小界面」默认实现；正式画布交 Codex |
| 版本控制 | Git（本项目目录内初始化） | 强制底线 |

## 3. 触发的按需模块

| 触发条件 | 引入模块 | 本次是否引入 |
| --- | --- | --- |
| 多实体/状态机/事务/重启恢复 | SQLite + SQLAlchemy + Alembic | ✅ |
| 长耗时任务、需排队与取消 | 持久化任务表 + worker 租约 + 轮询器 | ✅ |
| 大文件（图片/视频） | 本地文件目录 + 内容寻址 + 下载校验 | ✅ |
| 云端费用需要硬约束 | 预算闸门 + 用量台账 | ✅（本次新增，非手册默认项，但 PRD §10.7 要求） |
| RAG / 向量检索 | Chroma | ❌ 无需求 |
| Word/PDF 处理 | python-docx / pypdf | ❌ 无需求 |
| 登录与多用户 | 账号体系 | ❌ 单机单用户（PRD Q3） |
| 消息队列/Redis | Celery/RQ | ❌ 规模未到，且引入运维成本 |

## 4. 偏离或暂缓的默认方案

| 项 | 默认 | 本次 | 原因 / 影响 |
| --- | --- | --- | --- |
| 推理位置 | 产品自带推理（v0.2 版本地） | **云端（火山方舟）** | 需求方决定；**偏离原作业「全部本地推理」要求，PRD §0.2 已如实记录**；不得宣称端侧推理验收 |
| Python 版本 | 3.12 | 新建 venv 装 3.12 | 系统 3.9.6 不满足基线；不污染系统 Python |
| 正式前端 | 阶段 3 由 Codex 做 | 本阶段只做最小验收页 | 保证今天能亲手验证；正式画布仍属 Codex |
| 画布 | — | **暂缓**（仅草稿后端接口 + 最简展示） | PRD §7.3 明确列为延期 |
| 视频批量生产 | — | **暂缓**（仅单条 I2V + 批量提交后端能力） | 同上，不得包装成已完成 |
| 依赖安装 | — | **本阶段仅安装后端运行依赖**（httpx/pydantic/fastapi/sqlalchemy/pytest/ffmpeg） | 按你指令，不安装本地推理依赖、不下载模型权重 |

## 5. 强制底线检查

| # | 底线 | 本方案如何满足 |
| --- | --- | --- |
| 1 | 密钥不进仓库/前端/日志 | Key 只从 `.env` 读取；`.gitignore` 首条；日志脱敏中间件；前端只能调本地接口 |
| 2 | 长任务状态与人工确认点持久化 | SQLite 任务表；`remote_task_id` 落库；草稿快照；重启扫描恢复 |
| 3 | 接口定义请求/响应/错误；错误统一 `{"error":{"code","message"}}`；SSE 以 done/error 收尾 | 见架构方案 §9、§10 |
| 4 | 模型输出结构校验；超时/失败/重试 | Pydantic 校验云端响应；超时策略见 §8.4（**创建超时不重发**） |
| 5 | 高风险/花钱动作由确定性代码 + 人工确认约束 | 预算闸门 + 每次真实调用需显式提交；不自动扩量 |
| 6 | 上传校验格式/真实类型/大小/文件名；日志不记密钥与完整内容 | 见 §12 |
| 7 | 权限判断在后端 | 单机单用户，仅监听 127.0.0.1；后续多用户时在后端加 owner 判断 |
| 8 | 计费资源先告知费用 | PRD §8.4 已给估算与预算建议，**确认前不调用** |
| 9 | 不删已有功能/不擅自迁移 | 目录原为空；历史 PRD 已保留在 `docs/PRD/history/` |
| 10 | 不用 mock 冒充真实验证 | 证据分「模拟调用/真实云端调用/人工验收」三类；未跑写「未执行」 |
