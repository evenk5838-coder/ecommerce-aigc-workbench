## 前端本轮已纠正的契约误配

- 分镜审核改为 `POST /storyboards/{id}/review`，显式传 `approve`；生成分镜显式传 `confirm:true`，且只在用户已确认报价的按钮处理里调用。
- 创建镜头读取真实 `shot_ids/count` 回执，随后 GET 读取实体；GET 失败保留已创建编号和待核对状态，不再重复 POST。
- 创建时 `model_id` 位于请求根；镜头字段仅保存 `description/duration_s/motion`，提示词和参考图属于当前浏览器中的分镜生成输入。
- 状态接口实际返回嵌套 `take`、总数 `takes`、`films`；前端不把总数当历史列表、不把项目 `mode=done` 当 `full/clips`。
- 成片实测时长使用实际 `duration_ms`，空值保留未知；下载走 `assets/{asset_id}/file`。
- 导出使用真实 `download_url=/api/exports/{id}/file`，显示 `missing`；不虚构 ZIP 的素材编号或 `status=ready`。
- 模板的空运镜/节奏可显示为空；套用回执的 `created_shots` 数组按实际条目计数。
- 幂等回执 `idempotent_replay=true` 可以不带 `auto_film`，仍严格校验项目报价、模式与任务映射。报价合计按后端四位小数舍入检查。

## 仍需后端完成

### B0：文生视频入口实际被后端阻断（最优先；阻塞四模式验收）

静态证据：主仓 `backend/app/main.py:330–333` 的 `resolve_task` 对所有 `body.kind == "video"` 请求统一执行：

```python
if not body.input_asset_id:
    raise err("VALIDATION_FAILED", "视频任务需要 input_asset_id（首帧图）")
load_asset(body.input_asset_id)
```

因此显式传 `params.generation_mode="text_to_video"`、仅有合法提示词而无参考图的请求，也会在估价/提交的共同解析入口被拒绝。前端显示文生视频选项，不代表后端链路已可执行。`cloud_tasks.build_content` 虽能构建纯文字 content，但上游请求无法到达；该函数目前也只按是否带图片追加 image_url，没有独立的视频模式约束。

请按以下边界修复已有能力，不另起任务协议：

- 规范视频 `params.generation_mode` 为 `text_to_video / image_to_video`，图片继续使用 `text_to_image / image_to_image`。未知模式、模式与 kind 不匹配必须明确拒绝。
- 显式文生视频要求非空提示词，并校验所选模型真实支持该模式；不得强制参考图，也不得偷偷携带旧草稿/重试里的参考图。显式文生模式却携带图片时应明确拒绝冲突或采用已写入契约的可见处理，不得静默按图生执行。
- 显式图生视频必须提供可读取的有效图片；缺图、素材不存在、非图片或损坏图片应在估价/入队前给出明确错误。
- 保持旧 I2V 请求兼容：旧请求未传 generation_mode 且已有首帧图，仍按现有图生视频规则执行，并把唯一有效模式写入规范化参数。不要把旧请求无声改为文生视频；历史任务与费用记录不回写。
- 规范化后的模式、有效提示词、参考图及规格贯通 estimate → create → batch → worker/provider → retry；视频 effective 回显应包含实际模式，重试沿用本次规范化模式与输入，不能被旧参考图污染。
- 供应商 payload 明确分支：T2V 只含文字 content，I2V 含文字/首帧图片；依据图片真实 MIME 编码，不能仅凭界面标签或模型名字宣称某能力已接通。

### B1：当前版本确认链（阻塞完整内测验收）

证据：

1. `shots.update_shot/delete_shot` 失效时使用 `object_id=shot_id`，但 `review_storyboard` 确认时登记的是 `object_id=storyboard_id`，两者不匹配。
2. `generate_storyboard` 新建版本时没有显式失效旧版确认；`director.readiness` 用“任一 approved 分镜”计算通过数。
3. `scope._storyboard_for` 从所有 `status=approved` 版本里选择一张，并未证明它仍匹配当前镜头修订及当前有效确认。
4. `review_storyboard(approve=False)` 会更新状态，但没有对应失效已存在的 confirmation；运镜修改也未进入现有失效判断。

请统一“当前镜头修订 + 当前分镜版本 + 当前确认有效性”，保留历史，但历史确认不得授权当前输入。镜头输入变化、重做分镜、驳回已批准版本后，旧 scope 必须失效；未审核的新版本不能继承旧批准。提交阶段还应重新检查脚本确认，而不是只信任曾经报价。

### B2：服务端执行闸门（阻塞完整内测验收）

文档说镜头增删改排序均需脚本确认有效，但目前仅 `add_shots` 调用 `_require_script_confirmed`；更新、删除、排序、生成分镜、审核分镜未见同等检查。补齐必要的服务端校验，直接调 API 也不能跳过上游确认。不要依赖前端隐藏按钮。

### B3：导演台动作完整性

`director._STAGE_OF_ACTION` 列了 `compose_film/export`，但 `readiness` 当前没有将二者加入 `allowed_actions`。请按真实片段/成片状态返回交付阶段可执行动作，并明确回看历史与继续生成的区别。`current_stage`、阶段 `visible`、有效确认、动作许可需保持一致；不能让有旧产物的 done 状态越过已失效确认。

### B4：结构模板列表

已有保存、按 ID 查看与套用；未实现 `GET /api/structure-templates`。前端可以手工输入 ID，但“浏览已保存模板”无法完成。补列表接口，返回 `items[{template_id,name,latest_version,status?}]`，不返回伪造或临时缓存的列表。

### B5：历史分镜与片段的可读性

当前镜头接口只给最新分镜摘要及版本数，且摘要未包含 task_id；页面在分镜生成中刷新后无法从摘要恢复任务轮询。项目状态只给最新 take 及总数。前端不能从计数恢复历史版本；最新失败时也无法重新选择更早的成功 take。请补按镜头读取分镜版本、take 版本的接口或明确扩展已有响应，含真实 ID、版本、状态、素材和实测时长；最新分镜摘要补 task_id 以恢复进行中的任务。不要覆盖现有摘要字段。

### B6：时长校验模型与字段持久化边界

- 创建镜头支持根级 `model_id`，更新镜头却使用服务端默认模型验证时长。多模型原生时长不同，应给更新接口明确的模型校验上下文，或约定从项目/镜头持久化配置取值。
- 目前镜头接口不保存 `prompt/input_asset_id/model_id`；前端已明确标注提示词、参考图、模型选择保存在当前浏览器。若既定“跨设备/重新打开完整恢复创作输入”的验收要求包含这些字段，需要补持久化方案；不要静默丢弃却宣称已保存。
- scope 路由不接收 `overrides`。前端目前要求先保存镜头时长再报价，不提交未被支持的临时覆盖。

## 四种快捷生成入口边界

前端明确分为“图片生成：文生图 / 图生图”和“视频生成：文生视频 / 图生视频”，受各模型能力与可提交状态驱动。目前文生视频仍受 B0 的后端强制首帧校验阻断，四入口不能作为四模式已全部贯通的证据。图生方式要求参考图，文生方式不偷偷携带图片。请保持现有任务契约向后兼容，分别用隔离测试证明输入分支与供应商 payload；真实模型验证沿用用户已批准的明确范围，未经额外授权不新增付费调用。
