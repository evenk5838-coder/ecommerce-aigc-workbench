# 助手阶段一：模块划分与接口约定（开发前记录）

日期：2026-10-24｜阶段：**第一阶段基础开发**｜依据：PRD v0.9 §13、《提示词与行为规则 v0.2》、《前后端改动清单 v0.2》

> 本文先固定模块边界与工程默认值，避免把工程细节逐项抛回产品。
> 只做现有 MVP 增量：不改原工作台/素材/草稿/任务系统/手动生成路径。

## 1. 模块划分

```
backend/app/
├─ assistant/
│  ├─ provider.py     LLM 适配层（厂商可替换）+ 固定回复替身 + 未配置时的 Unavailable
│  ├─ tools.py        工具执行器（只读 + 报价），**不含 confirm / submit**
│  ├─ service.py      会话、brief、轮次/工具/消耗限制、用量记录
│  ├─ approval.py     报价单、用户确认、批准消费（事务）+ 幂等
│  └─ router.py       /api/assistant/* 路由
├─ db.py              +5 张表（会话/ brief / 报价 / 批准 / 助手用量）与 transaction()
└─ main.py            仅接入 router + POST /api/tasks 接受 approval_id（手动路径不变）
```

### 设计要点（技术默认值 + 理由）

| 决策 | 默认值 | 理由 |
| --- | --- | --- |
| LLM 接入 | `ASSISTANT_PROVIDER=none`（默认不可用） | 未选型前不假装接通；`GET /api/assistant/status` 明确返回不可用 |
| 适配层形态 | 单一 `chat(messages, tools) → {reply, tool_calls, usage}` | 厂商差异只在这一层；换型不改业务代码 |
| 流式 | 首版不做 | 回复短，降低代理与前端复杂度（清单 D1） |
| brief 存储 | 新增 `assistant_briefs` 表（不塞草稿 `content`） | 草稿 content 由前端画布独占，混写易造成互相覆盖；独立表可版本化、可审计 |
| 报价 | 新增 `POST /api/assistant/quote`，内部复用 `main.resolve_task` + 计价 | **不改** `/api/tasks/estimate` 语义（PRD/清单要求） |
| 确认 | `POST /api/assistant/confirm`，仅前端调用；**不是 LLM 工具** | 模型不能自我批准 |
| 批准 | 一次性、绑定 `plan_hash` + 会话/项目 + 有效期 | 参数变即失效；重复提交只对应一个任务 |
| 提交 | 仍用 `POST /api/tasks` + `approval_id` | 不新增平行提交入口；手动路径无 approval 时行为不变 |
| 来源 | `approval_id` 存在 → 后端强制 `caller_id="assistant"`，忽略请求里的值 | 不能靠改 `caller_id` 绕过确认 |
| 一致性 | 批准消费与任务写入在**同一 SQLite 事务**内 | 避免"批准已用但任务没建" |
| 幂等键 | 助手路径 `client_request_id = "apv:<approval_id>"` | 重复提交命中幂等，返回同一任务 |
| 限制 | `assistant_sessions` 计数 + 环境变量默认值 | 仅约束助手；不影响手动接口 |
| 用量 | 新增 `assistant_usage`（LLM token / 工具 / 提交事件） | 与 `tasks.cost_cny` 分开，便于后续统一换算 |

## 2. 接口约定（本阶段实现）

| 方法 | 路径 | 用途 | 是否新增 |
| --- | --- | --- | --- |
| GET | `/api/assistant/status` | 助手可用性（未配置 LLM 时明确不可用） | 新增 |
| POST | `/api/assistant/chat` | 对话（首版非流式） | 新增 |
| GET/PUT | `/api/assistant/brief?project_id=` | 项目 brief 读取/保存 | 新增 |
| POST | `/api/assistant/quote` | 助手报价（记录报价单） | 新增 |
| POST | `/api/assistant/confirm` | 用户界面确认 → 批准 | 新增 |
| GET | `/api/assistant/usage` | 助手用量（与生成用量分开） | 新增 |
| POST | `/api/tasks` | 增加可选 `approval_id` | 增量 |

**工具白名单**（LLM 可调用）：`list_models`、`list_templates`、`get_template`、`list_assets`、`get_brief`、`quote`、`get_task`、`cancel_task`。
**禁止作为工具**：`confirm`、`submit`、任何额度/积分操作。

## 3. 与现有文档的差异声明

| 文档写法 | 本阶段实现 | 原因 |
| --- | --- | --- |
| "brief 存草稿 `content`" | 独立 `assistant_briefs` 表 | 草稿 content 是前端画布独占，混写会互相覆盖 |
| "`estimate` 返回 `quote_id`" | 独立 `/api/assistant/quote` 返回 | 要求保持 `estimate` 原有语义 |
| "优化/咨询无费用"（旧表述） | 已更正为：**不产生图片/视频生成费用，但产生 LLM 用量** | 避免把"无生成费用"误读为"无成本" |

## 4. 环境变量（默认值即推荐值）

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `ASSISTANT_PROVIDER` | `none` | `none` / `fixed`（测试替身）/ 未来真实厂商名 |
| `ASSISTANT_MODEL` | `""` | 运行时型号（待确认后填） |
| `ASSISTANT_MAX_QUESTIONS` | `4` | 单会话提问上限（建议值） |
| `ASSISTANT_MAX_TURNS` | `12` | 单会话轮次上限 |
| `ASSISTANT_MAX_TOOL_CALLS_PER_TURN` | `3` | 单轮工具调用上限 |
| `ASSISTANT_MAX_SESSION_COST_CNY` | `0`（不限） | 单会话 LLM 估算成本上限，0=不限 |
| `ASSISTANT_QUOTE_TTL_S` | `600` | 报价有效期 |
| `ASSISTANT_APPROVAL_TTL_S` | `600` | 批准有效期 |

## 5. 验收对应

| 验收要求 | 落点 |
| --- | --- |
| 仅优化不提交 | `intent=optimize_only` 时 `quote` 工具被拒；无生成任务 |
| 未确认不能提交 | 无 `approval_id` 的助手请求无法产生 `origin=assistant` 任务；工具表无 submit |
| 改参数旧批准失效 | `plan_hash` 不一致 → 409 |
| 重复提交不重复建任务 | `apv:<id>` 幂等 + 批准一次性 |
| 不能自我确认/伪装来源 | 无 confirm 工具；`caller_id` 由后端强制 |
| 重启后记录保留 | SQLite 持久化（会话/报价/批准/用量） |
| 手动操作不回归 | 无 `approval_id` 时走原路径 |
