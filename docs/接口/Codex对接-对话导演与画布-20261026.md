# Codex 对接：对话导演 + 自由画布（已实现）

日期：2026-10-26｜对应后端提交见 §9｜**B0–B6 未重复开发**
Fixture：`docs/接口/样例-对话导演与画布.json`（真实结构，替身 LLM 产出）

> 三个动作严格分开：
> **自动保存草案**（后端落库，`confirmed=false`）≠ **用户确认**（`/api/scripts/{id}/confirm`、`/api/storyboards/{id}/review`）
> ≠ **授权付费生成**（`/scope` + `/confirm` + `/generate`）。
> 对话里说"确认了"或模型返回 `confirm=true` 都**不能**代替上述请求。

---

## 1. `POST /api/projects/{id}/director/chat`

请求：

```json
{
  "client_request_id": "user-generated-uuid",
  "message": "两个镜头，先整体再瓶盖",
  "session_id": "asst_optional",
  "selected_asset_ids": ["asset_…"],
  "expected_workflow_revision": null
}
```

- `client_request_id` **必填**（幂等 + 断线恢复）；`message` 必填。
- `session_id` 省略则自动创建**绑定该项目**的会话；传入其它项目的会话 → **409 `PROJECT_SESSION_MISMATCH`**。

响应（节选，完整见 fixture）：

```json
{
  "session_id": "asst_…", "request_id": "user-generated-uuid",
  "request_status": "completed",
  "reply": "已保存脚本与镜头计划草案，请先确认脚本。",
  "reply_type": "proposal_ready",
  "artifacts": [
    {"type":"script","proposal_id":"prop_…","proposal_version":1,
     "target_id":"scr_…","target_version":1,"persistence":"saved","confirmed":false},
    {"type":"shot_plan","proposal_id":"prop_…","proposal_version":1,
     "target_id":"scr_…","target_version":1,"persistence":"saved","confirmed":false}
  ],
  "actions": [{"type":"confirm_script","target_id":"scr_…","target_version":1,
               "requires_user_action":true}],
  "current": {"stage":"script","script":{…},"confirmation":{"confirmed":false,"valid":false}},
  "allowed_actions": ["edit_brief","regenerate_script","confirm_script"],
  "workflow_revision": 5,
  "usage": {"input_tokens":860,"output_tokens":180,"cost_cny":0.0032,
            "note":"费用为应用侧估算，非供应商账单"},
  "budget": {"per_call_limit_cny":0.05,"session_limit_cny":0.30}
}
```

**前端要点**
| 字段 | 用法 |
| --- | --- |
| `artifacts[].persistence` | 只能是 `saved`；若为其它值表示未保存（当前实现只返回 saved 的产物） |
| `artifacts[].confirmed` | **恒为 false**（草案）。不要自行改成 true |
| `actions[]` | 由后端按真实 DB 状态生成；`confirm_script` 要调 `/api/scripts/{id}/confirm` |
| `usage.cost_cny` | 估算；`null`/缺失时显示"费用未知"，不要显示 0 |
| `workflow_revision` | 后续 apply/编辑用它做并发基线 |

**错误码**

| code | HTTP | 场景 |
| --- | --- | --- |
| `VALIDATION_FAILED` | 400 | message/client_request_id 为空 |
| `PROJECT_SESSION_MISMATCH` | 409 | 会话属于别的项目 |
| `IDEMPOTENCY_CONFLICT` | 409 | 同 `client_request_id` 不同内容 |
| `DIRECTOR_REQUEST_PENDING` | 409 | 该请求仍在处理中 |
| `ASSISTANT_UNAVAILABLE` | 503 | 未配置 LLM |
| `ASSISTANT_BUDGET_EXCEEDED` | 429 | 单次/会话预算不足（`detail.scope`） |
| `TOOL_FORBIDDEN` | — | 模型试图调用 confirm/submit/generate（内部拒绝，不会执行） |

## 2. 恢复与幂等

| 端点 | 用途 |
| --- | --- |
| `GET /api/projects/{id}/director/requests/{client_request_id}` | 回执：`completed` 返回原响应；`pending` 提示稍后再查；`failed` 带 `error_code` |
| `GET /api/projects/{id}/director/messages?cursor=&limit=` | **分页**读完整对话（不依赖 LLM 8 条窗口） |
| `GET /api/projects/{id}/director/proposals?kind=` | 提案列表（brief / script / shot_plan，含版本与状态） |
| `POST /api/projects/{id}/director/proposals/{id}/apply` | 应用提案（用户动作，**不生成**） |

幂等行为：同键同内容 → 返回原响应并带 `idempotent_replay:true`，**不重复调用 LLM、不重复落库**。

## 3. 提案应用（`apply`）

```json
POST /api/projects/{id}/director/proposals/{proposal_id}/apply
{"expected_version": 1, "user_action": "apply_proposal"}
```

| 提案类型 | 应用效果 | 拒绝条件 |
| --- | --- | --- |
| `brief` | 合并进项目 brief（未提及字段不动），返回 `stale` | 字段非法 |
| `script` | **不复制版本**（保存时已落 `script_versions`），返回 `script_id/version` 与确认提示 | 脚本已被删除 |
| `shot_plan` | 生成镜头（复用 `shots.add_shots`），返回 `shot_ids` | 脚本未确认 / 脚本已升版 / 项目已有镜头 |

- 版本不匹配 → **409 `PROPOSAL_VERSION_CONFLICT`**；条件不满足 → **409 `PROPOSAL_NOT_APPLICABLE`**。
- **应用不创建任何图片/视频任务**。

## 4. 自由画布（节点持久化）

| 端点 | 用途 |
| --- | --- |
| `GET /api/projects/{id}/canvas` | 节点 + 布局 + 视口 + `last_execution`（只读） |
| `PATCH /api/projects/{id}/canvas` | 保存布局/节点配置（**不生成**） |

**节点结构**

```json
{"node_id":"node_video_2","type":"video",
 "position":{"x":640,"y":420},
 "config":{"generation_mode":"text_to_video","model_id":"doubao-seedance-1-0-pro-fast-251015",
           "prompt":"瓶盖特写","params":{"duration":5,"ratio":"9:16","resolution":"720p"}},
 "binding":{"shot_id":null},
 "config_revision":1}
```

**关键规则**
1. **只移动节点 / 缩放视口** → `layout_revision+1`，`config_revision` 不变，**报价与确认不失效**。
2. **改生成配置**（prompt/素材/模型/模式/规格）→ `config_revision+1`，并使该项目**整组报价失效**（`invalidated:["scope"]`）。
3. 每个节点**各自保存** prompt/素材/模式/模型/规格，互不影响（fixture 中 `node_video_1` 为 I2V、`node_video_2` 为 T2V）。
4. 校验：未知模式 / 时长越界 / 图生节点缺素材 / 文生节点带素材 / 引用其它项目对象 / 连线成环 → 4xx。
5. `last_execution`（task/asset/耗时）**由服务端从真实任务读取**，PATCH 传了也会被忽略。

**并发**：PATCH 可带 `expected_layout_revision`（整体）与 `expected_config_revision`（单节点），不匹配 → 409 `CANVAS_REVISION_CONFLICT`。

## 5. 前端接入手势建议

```
用户输入 → director/chat（带 client_request_id）
  → 渲染 reply + artifacts（显示"草案已保存，未确认"）
  → 按 actions 渲染单一主按钮（确认脚本 / 应用计划 / 报价）
  → 用户点击 → 调既有 /scripts/{id}/confirm 或 /proposals/{id}/apply
  → 重新 GET /director 拿真实 readiness（不要本地推进阶段）
断线/超时 → GET /director/requests/{crid} 查回执，不要重发
画布拖动 → PATCH /canvas（只传 position），不会影响报价
画布改参数 → PATCH /canvas（传 config），预期 invalidated 提示重新报价
```
