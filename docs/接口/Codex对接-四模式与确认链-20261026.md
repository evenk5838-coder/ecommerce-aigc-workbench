## 1. B0：四种生成方式（已修，**T2V 不再被阻断**）

### 1.1 `generation_mode` 规范

| kind | 合法 mode | 必填输入 |
| --- | --- | --- |
| image | `text_to_image` / `image_to_image` | 图生图必须有 `input_asset_id` |
| video | `text_to_video` / `image_to_video` | **文生视频只给 prompt**；图生视频必须有首帧图 |

- 未知 mode、mode 与 kind 不匹配 → 400 `VALIDATION_FAILED`（`detail.allowed` 给出允许值）。
- 模型不支持该模式 → 400 `MODEL_CAPABILITY_MISMATCH`（`detail.field=generation_mode`）。

### 1.2 文生视频（T2V）

```json
POST /api/tasks/estimate
{"kind":"video","model_id":"doubao-seedance-1-0-pro-fast-251015",
 "params":{"generation_mode":"text_to_video","prompt":"瓶子缓慢旋转",
           "duration":5,"ratio":"9:16","resolution":"720p"}}
```

响应（节选）：

```json
{"kind":"video","submittable":true,"blocked_reasons":[],
 "estimated_cost_cny":0.4536,
 "effective":{"generation_mode":"text_to_video","duration":5,"ratio":"9:16",
              "resolution":"720p","generate_audio":false},
 "side_effects":{"task_created":false,"model_called":false}}
```

- **不要求 `input_asset_id`**；
- 显式 T2V 又传 `input_asset_id` → **400 `GENERATION_MODE_CONFLICT`**（不会静默按图生执行）；
- 参数里残留的 `input_asset_id` 会被剥离；
- prompt 为空 → 400 `VALIDATION_FAILED`。

### 1.3 图生视频（I2V）

- 缺首帧 → 400 `REFERENCE_IMAGE_REQUIRED`；素材不存在 → 404 `ASSET_NOT_FOUND`；
  非图片 → 400 `ASSET_NOT_IMAGE`；损坏 → 400 `INVALID_REFERENCE_IMAGE`。
- 供应商 payload：文字 + 首帧图，**按真实 MIME**（示例：`data:image/jpeg;base64,…`）。

### 1.4 旧请求兼容

- **未传 mode + 有首帧** → 归一化为 `image_to_video` 并按 I2V 执行（不会被改成 T2V）；
  规范化后的 mode 写入 `params.generation_mode`。
- **未传 mode + 无首帧** → 仍按旧行为拒绝（`VALIDATION_FAILED`）。
- 历史任务/费用/产物**不改写**；重试沿用本次规范化模式（T2V 重试不带图，I2V 重试保留首帧）。

### 1.5 前端注意

| 场景 | 正确做法 |
| --- | --- |
| 文生视频 | 只发 `prompt`，**不要**带上一张"顺手"的图 |
| 从图生切换到文生 | 显式清空参考图，否则会 400 `GENERATION_MODE_CONFLICT` |
| 批量混合 | 每项各自带 mode；非法项**整批拒绝**（不产生半成品） |
| 展示 | 用 `effective.generation_mode` 显示实际模式，不要按 UI 标签推断 |

## 2. B1：当前版本确认链

**规则**：确认绑定「对象 + 版本 + 镜头修订」；历史确认保留但**不授权当前输入**。

| 变化 | 结果 |
| --- | --- |
| 改镜头描述 / 时长 / **运镜** | 该镜**所有**分镜版本确认 → `invalidated`（`reason=shot_changed`）；旧 scope 提交 → 409 `SCOPE_STALE` |
| 重做分镜（新版本） | 旧版本确认 → `invalidated`（`reason=storyboard_regenerated`）；新版本**未确认** |
| 驳回已批准版本 | 该版本确认 → `invalidated`（`reason=storyboard_rejected`） |
| 分镜基于旧镜头修订 | 审核 → 409 `STORYBOARD_STALE`（`detail.storyboard_revision` / `shot_revision`） |
| 报价后改 brief | 提交时复查脚本确认 → 409 `SCRIPT_NOT_CONFIRMED` |

`GET /api/projects/{id}/director` 的 `current.confirmation` 现在是**当前有效**判定，
`warnings[].reason` 给出失效原因。样例见 `样例-四模式与确认链.json` 的
`B1_confirmation_after_change`（`{"confirmed":true,"valid":false,"reason":"shot_changed"}`）。

## 3. B2：服务端执行闸门（直接调 API 也会拦）

以下接口现在都会校验**脚本确认有效**，否则 409 `SCRIPT_NOT_CONFIRMED`：

`POST /api/projects/{id}/shots`、`PATCH /api/shots/{id}`、`DELETE /api/shots/{id}`、
`POST /api/projects/{id}/shots/reorder`、`POST /api/shots/{id}/storyboard`、
`POST /api/storyboards/{id}/review`。

> 前端不要依赖隐藏按钮；**失效后按钮应置灰，但后端也已拦截**。

## 4. B3：导演台动作完整性

`allowed_actions` 现在随真实状态出现：

| 条件 | 追加动作 |
| --- | --- |
| 全部镜头分镜有效通过 | `quote_generation`、`confirm_generation` |
| 存在成功片段 | `compose_film` |
| 存在 ready 成片 | `export` |

- 旧确认失效 → `current_stage` 回退（不会停在 done），`confirm_generation` 不再出现。
- 前端据此决定"交付阶段"按钮是否可用。

## 6. B5：历史分镜与片段（新增，供回看/回选）

**GET `/api/shots/{shot_id}/storyboards`**

```json
{"items":[{"storyboard_id":"sb_…","shot_id":"shot_…","version":2,"task_id":"task_…",
           "asset_id":"asset_…","status":"draft","shot_revision":2,
           "reject_reason":null,
           "confirmation":{"confirmed":false,"valid":false,"reason":"never_confirmed"},
           "created_at":1792…}]}
```

**GET `/api/shots/{shot_id}/takes`**

```json
{"items":[{"take_id":"take_…","task_id":"task_…","asset_id":"asset_…",
           "status":"succeeded","duration_ms":5042,"cost_cny":0.436,
           "spec":{"duration_s":5,"ratio":"9:16","resolution":"720p"},
           "created_at":1792…}]}
```

- 分镜列表含 `task_id` → **刷新后可从摘要恢复任务轮询**；
- take 列表含失败项与 `duration_ms` → 最新失败时可**回选更早的成功 take**；
- 现有 `shot.storyboard` 摘要字段**未改动**（仅新增端点）。

## 7. B6：时长校验的模型上下文 + 字段持久化边界

**PATCH `/api/shots/{id}`** 新增可选 `model_id`：

```json
{"duration_s":8,"model_id":"doubao-seedance-1-0-pro-fast-251015","expected_revision":1}
```

- 传了 `model_id` → 按**该模型原生区间**校验时长；不传 → 用当前可用默认模型。
- 例：用 `seedance-2-0-mini`（4–15s）校验 `duration_s=3` → 400 `MODEL_CAPABILITY_MISMATCH`。

**持久化边界（明确）**：

| 字段 | 是否后端持久化 |
| --- | --- |
| `seq` / `duration_s` / `description` / `motion` | ✅ 存 `shots` 表 |
| 分镜生成用的 `prompt` / `input_asset_id` / `model_id` | ❌ **不存**（前端在浏览器保存，见 take 的 `spec` 快照） |
| 报价临时 `overrides` | ❌ 不支持；请**先保存镜头时长再报价** |

> 如果后续验收要求"重新打开项目可完整恢复创作输入"，需要单独设计持久化（本轮未做，不宣称已保存）。
