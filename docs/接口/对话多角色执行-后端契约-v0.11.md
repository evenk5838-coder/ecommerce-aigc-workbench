# 对话多角色执行：后端契约 v0.11

日期：2026-10-27。适用范围：新对话主控、真实画布产物、用户确认动作、逐镜生成、批准后自动拼接成片及独立合成。本批后端已做隔离验证；正式前端尚未接入新 API，真实文本／图片／视频模型待验。本页不替代旧接口，不代表完整产品已验收。

关联：[PRD](../PRD/PRD.md)、[切片 1 契约](接口契约-v0.11-切片1.md)、[节点执行与删除撤销契约](节点执行与删除撤销-后端契约-v0.11.md)、[本批阶段交接](../阶段文档/对话多角色执行-后端-20261027.md)。

## 1. 主控与授权边界

一个项目会话承担编剧、导演、摄影师、剪辑师职责，角色由服务端当前产物和选中节点推导。无需四个独立会话；角色切换也不是支付或执行授权。

正常路径为：说明想法 → 必要澄清 → 保存脚本节点 → 用户确认脚本 → 建立逐镜图片节点和生成方案 → 用户确认该组生成 → 读取图片产物 → 建立视频节点和生成方案。视频阶段可交付逐条素材，也可在用户确认视频方案时一并批准按明确顺序拼接成片。

模型可以保存创作内容、修改指定节点、准备报价和合成方案；只有用户动作入口可以确认脚本或提交生成／合成。聊天中模型说“已确认”“正在生成”不改变业务状态。脚本确认不授权图片或视频费用。图片／视频任务始终复用现有节点执行、模型能力、预算及引用校验。

`output_mode=clips` 交付逐条素材；已有视频可另经 `prepare_composition` 和 `confirm_compose` 合成。`output_mode=film` 仅接受视频生成节点，一次 `confirm_generate` 批准本组视频生成及其全部成功后按 `node_ids` 明确顺序完整拼接；通过 `prepare_video_nodes` 建立时，顺序来自 `sources` 数组。自动合成不再调用模型或要求第二次合成确认。这次批准不包含前序图片生成、其他节点、未来新版本或失败后的重新生成。

## 2. HTTP 入口

所有路径以 `/api` 开头，成功直接返回 JSON；业务错误沿用 `{ "error": { "code", "message", "detail"? } }`。请求体 Pydantic 校验失败为 HTTP 422 的 `detail` 结构，前端需同时兼容。

| 方法与路径 | 用途 | 是否开始工作 |
| --- | --- | --- |
| `POST /projects/{project_id}/director/conversation` | 发送新流程对话 | 可能调用文本模型和保存内容；不提交图片／视频／合成 |
| `GET /projects/{project_id}/director/conversation/state` | 真实角色、当前内容、最近结果及确认动作 | 只读 |
| `GET /projects/{project_id}/director/conversation/requests/{client_request_id}` | 恢复本次对话回执及已提交工具产物 | 只读，不重放模型 |
| `GET /projects/{project_id}/director/actions/{action_id}` | 确认动作及实际任务进展 | 只读，不自动重试 |
| `POST /projects/{project_id}/director/actions/{action_id}/confirm` | 用户确认一个冻结动作 | 按动作种类确认脚本、提交一组任务或提交一次合成 |

完整历史继续用 `GET /projects/{project_id}/director/messages?cursor=...&limit=30`。`state` 仅返回最近一轮 outcome／artifacts 和最近 20 个动作，不是完整聊天历史。

旧 `/director/chat`、`/director/requests/{id}`、提案和旧生产链接口保留。新接口不接收旧 `intent`、`selected_asset_ids` 或 `user_action` 字段；新旧对话共用项目请求号约束，同一请求号跨入口使用会明确冲突。新回执入口拒绝把旧流程回执当作新流程结果读取。

## 3. 发送对话

```json
{
  "message": "这只白色水杯做两个镜头，先杯身再杯口，暖色晨光，请直接写脚本",
  "client_request_id": "conversation-unique-id",
  "session_id": "asst_existing_or_omit",
  "selected_node_ids": [],
  "expected_workflow_revision": 123456789
}
```

| 字段 | 规则 |
| --- | --- |
| `message` | 必填、非空，最多 20000 字符 |
| `client_request_id` | 必填、非空，最多 200 字符；一次用户发送对应一个稳定请求号 |
| `session_id` | 可省略；提供时必须属于本项目，不能跨项目串会话 |
| `selected_node_ids` | 可省略，默认空；最多 40 项，必须都属于当前项目，服务端在模型调用前校验 |
| `expected_workflow_revision` | 可省略；若提供，必须等于服务端当前令牌；是相等性校验值，不自行递增 |

多余字段、数字冒充字符串、布尔值冒充修订号等不会被宽松接受。`workflow_revision` 与 `layout_revision`、节点 `config_revision` 各有用途，不可互换。布局拖动不代表内容确认或新生成授权。

下例为字段示意，ID 和用量不是一次新的真实调用记录：

```json
{
  "flow_version": 2,
  "session_id": "asst_example",
  "request_id": "conversation-unique-id",
  "request_status": "completed",
  "reply": "脚本已放入画布，请查看并确认。",
  "reply_type": "saved",
  "outcome": {"status": "saved", "node_ids": ["script"]},
  "artifacts": [{
    "type": "script", "kind": "script", "node_id": "script",
    "proposal_id": "prop_example", "version": 1,
    "target_id": "scr_example", "target_version": 1,
    "saved": true, "persistence": "saved", "confirmed": false
  }],
  "actions": [{
    "action_id": "dact_example", "kind": "confirm_script",
    "node_ids": ["script"], "script_id": "scr_example", "script_version": 1,
    "status": "proposed", "action_status": "proposed",
    "requires_user_action": true, "expired": false, "stale": false,
    "estimated_cost_cny": 0, "expires_at": 1793198073
  }],
  "current_role": "writer",
  "current": {"project_id": "prj_example", "script": {"script_id": "scr_example", "version": 1, "confirmed": false}},
  "usage": {"input_tokens": 0, "output_tokens": 0, "cost_cny": 0, "estimated_cny": 0},
  "tool_calls": [],
  "rounds": [],
  "workflow_revision": 123456790
}
```

`current` 实际还包含 brief、脚本正文、镜头等项目内容；示例省略。`tool_calls` 和 `rounds` 是诊断信息，不能用来替代产物和任务状态，也无需直接展示给用户。

| `outcome.status` | 含义与前端处理 |
| --- | --- |
| `saved` | 有真实已保存产物或已准备动作；不等于媒体已生成。按 `artifacts`／`actions` 定位，刷新画布 |
| `clarify` | 明确缺少必要信息；附 `missing_fields`，继续对话，不创建虚假节点 |
| `message` | 讨论方案，无生成结果 |
| `failed` | 本轮没有完成产物／动作；附 `error={code,message}` |
| `partial` | 部分产物／动作已保存，其余失败；保留成功部分，显示未完成原因 |

HTTP 200 和 `request_status=completed` 仅说明该轮有最终业务结果，仍须检查 outcome。运行阶段的明确失败会保存失败回执；前置校验错误可以直接返回 HTTP 错误。`usage.cost_cny` 是文本调用账目字段；当供应商返回未知时可能带 `has_unknown_cost=true` 并保留估算，不能描述为精确实际账单。

## 4. 角色、选中节点和中途进入

`GET .../conversation/state?selected_node_id=node-a&selected_node_id=node-b` 使用重复的单数查询参数；POST 使用复数数组 `selected_node_ids`。

`state` 返回 `project_id,session_id,current_role,creation,project,outcome,artifacts,actions,workflow_revision`。`creation` 包含选中 ID、节点 config／binding／修订号、素材摘要、执行结果、当前脚本确认状态。上下文最多 40 个节点，选中节点优先；长文本会截断并设置 `content_truncated`，集合截断用 `nodes_truncated` 明示。它不替代完整画布 GET。

| `current_role` | 当前规则 |
| --- | --- |
| `writer` | 默认、新脚本未确认或选中自由文本；新脚本未确认时不因旧成片自动跳走 |
| `director` | 当前脚本已确认，或选中尚无成功图片结果的图片节点 |
| `cinematographer` | 选中已有图片产物／导入图片，或待生成视频节点 |
| `editor` | 选中已有视频产物／导入视频；多选有视频结果时优先进入剪辑职责 |

角色反映真实可用内容和当前选择，不是按模型自称推进的硬编码四步进度条。

- 项目脚本使用稳定节点 ID `script`，正文通过脚本版本绑定读取，不复制为另一个自由文本节点。
- 自由文本可独立用于建立图片节点；不强制补一个项目脚本。
- 导入图片或已有成功图片可以直接建立视频节点；冻结明确的 `input_asset_id`、来源节点／执行／文件摘要，不引用一张“可能是最新”的图片。
- 已有视频可以直接准备合成；用户需明确顺序，不以画布横坐标推测顺序。
- “只改第二镜”应更新该节点当前版本，只对该节点准备新报价；其他节点、顺序及旧成功产物保留。

## 5. 工具边界与真实产物

以下是服务端给模型的工具，**不是新增的公开 HTTP 路由**。模型不能获得确认或提交工具。

| 工具 | 关键入参 | 结果／限制 |
| --- | --- | --- |
| `get_creation_context` | 可选 `selected_node_ids` | 当前项目真实上下文，只读 |
| `list_models` | 可选 kind 为 image 或 video | 实际模型与能力，参数以返回值为准 |
| `write_script` | `summary,shots?,base_version?` | 写真实脚本、稳定节点、提案、确认动作和工具回执；修改已有脚本必须提供当前 base_version |
| `prepare_script_confirmation` | `script_id,expected_version` | 为当前已有脚本恢复／更新确认入口；不重写、不确认 |
| `prepare_storyboards` | `source_node_id,expected_source_revision,model_id,params?,shots` | 从已确认的当前脚本或自由文本建立逐镜 image 节点；对话声明最多 20 镜；自动准备该组报价，零生成任务 |
| `prepare_video_nodes` | `model_id,params?,sources,output_mode?` | 从明确图片 asset／成功输出建立 video 节点；sources 含 asset_id、prompt，节点来源还需当前修订；按 sources 顺序准备 clips 或 film 方案，零生成任务 |
| `update_node` | `node_id,expected_config_revision,config` | 仅 text/image/video；config 与 params 局部合并，未给字段保留；类型和 binding 不可改；媒体仅报价该节点 |
| `prepare_generation` | `node_ids,expected_revisions,output_mode?` | 1–20 个节点，修订映射须完全匹配；接受 clips 或 film，film 只能含视频节点并冻结 node_ids 顺序；不入队 |
| `prepare_composition` | `sources,title?` | 有序、可读取的视频；来源含 asset_id，可明确 node_id／execution_id；只准备合成 |
| `respond_to_user` | `kind,message,missing_fields` | clarify 必须列必要缺项；discuss 不列缺项；不以“稍等”代替保存工具 |

四种生成方式仍以 `generation_mode=text_to_image|image_to_image|text_to_video|image_to_video` 明确区分。图生模式必须有有效图片引用；从图生改文生时，局部修改需要明确 `input_asset_id=null`。尺寸、比例、清晰度、视频原生时长按模型能力校验，不把任意提示词中的数值当作支持规格。

工具写入由项目、请求号、工具名、规范化参数 hash 保证幂等，产物和工具回执同事务。保存新脚本时，脚本版本、提案、canonical 节点、`confirm_script` 动作及工具回执同一事务提交：动作或回执写入失败全部回滚；提交后丢失最终对话响应，回执仍能读出脚本和动作。

`prepare_script_confirmation` 校验当前最新脚本版本和 canonical 绑定。相同请求重放原动作，即便它已过期也不静默续期；显式新请求可为当前脚本准备新动作。旧版本、跨项目或被替换的节点不会获得可用确认。

每个供应商 `assistant.tool_calls` 都有匹配的 `tool_call_id` 结果。保存已成功后，同批后续工具会得到明确 deferred 结果，等待下一次用户决策；不会产生孤立工具调用。普通无工具回复有一次修复机会，仍无实际动作／有效澄清则失败。已保存内容不因后续报价失败被删除。

新图片／视频节点以节点执行和素材为事实来源，不伪造旧 `storyboards`／`takes` 成功记录；旧流水线按钮不能被当作新流程状态的唯一依据。

## 6. 用户确认动作

请求体严格只有以下两项，动作 ID 来自服务端，不由模型或前端伪造：

```json
{"client_request_id":"confirm-unique-id","user_action":"confirm_generate"}
```

| 动作 kind | user_action | 冻结范围和提交行为 |
| --- | --- | --- |
| `confirm_script` | `confirm_script` | 最新脚本 ID／版本／内容 hash、项目需求 hash、canonical 节点数据库身份；24 小时；确认状态与动作回执同事务 |
| `generation` | `confirm_generate` | 节点 ID／config_revision、实际模型／提示词／规格／引用、每节点 quote、总估算及 output_mode／scope；film 同时冻结视频顺序和完整拼接范围；有效期取报价最早到期时间，全部校验和整组预算通过才原子入队 |
| `composition` | `confirm_compose` | 有序来源 asset／节点／execution／SHA／实际探测时长等；10 分钟；确认只提交持久化本地合成任务，不调模型 |

相同 action + 相同确认请求号返回原回执；同 action 换请求号或同确认请求号跨 action 使用会冲突。响应丢失后保留该请求号并读取原动作，不能换新号重试提交。

三类动作共同含 `action_id,kind,status,action_status,request_id,requires_user_action,estimated_cost_cny,expires_at,expired,submit_client_request_id`；通用 action GET／confirm 还附真实 `current_role,workflow_revision`。

- 脚本动作另含 `script_id,script_version,node_ids,stale,result`。`status=completed` 表示脚本确认已写入，尚未生成图片。
- 生成动作另含 `node_ids,quotes,output_mode,batch_id,tasks,executions,auto_film,scope,media_status,composition,error`。未确认时 status 与 media_status 均为 proposed；`action_status=submitted` 表示已受理，之后 `media_status=running|completed|partial|failed` 从本次 execution 和可用素材聚合。clips 的 `status` 与 `media_status` 一致；film 的 `status` 还包括成片结果，不能在镜头完成时提前显示成片完成。旧成功结果可继续显示，但不能据此把本次失败算作成功。
- 合成动作另含有序 `sources,title,no_trim=true,composition_id,job,asset_id,asset,result_node_id,planned_duration_ms,actual_duration_ms,asset_available,asset_error,generation_action_id`。worker 使用真实 FFmpeg，发布素材节点和成功回执同事务；读取时再次检查文件可用性。仅 `asset_available=true` 才返回可用的 `asset_id` 和 `actual_duration_ms`。源文件改变、失败、超时或时长不一致不会被描述为可用成片。当前是完整片段拼接，不提供剪裁、配乐、字幕、转场或自动选片。

film 生成方案的授权范围示意如下；它随报价展示并写入提交回执，`composition_cost_cny=0` 表示本地拼接不另收模型费用，不表示视频生成免费：

```json
{
  "output_mode": "film",
  "auto_film": true,
  "node_ids": ["video-blue", "video-red"],
  "scope": {
    "generate": true,
    "compose": true,
    "ordered_node_ids": ["video-blue", "video-red"],
    "no_trim": true,
    "composition_cost_cny": 0
  },
  "action_status": "submitted",
  "status": "running",
  "media_status": "completed",
  "composition": {"status": "waiting", "reason": "preparing"},
  "error": null
}
```

film 调度只使用该确认回执中每个节点对应的精确 execution／task／quote，不能替换成节点后来生成的“最新成功版本”，也不按布局位置排序。全部镜头成功且源素材可读取后，后台调度器原子写入合成动作、队列和生成回执关联，再执行本地合成；GET 不触发该调度。自动合成的嵌套动作通过 `generation_action_id` 关联原批准，`requires_user_action=false`，没有独立的 `confirm_compose` 请求；前端不因嵌套动作的 `expired` 字段再次要求确认。

| film 读取结果 | 前端解释 |
| --- | --- |
| `composition={status:waiting,reason:media_pending}` | 本组视频仍在生成 |
| `media_status=completed`，composition 等待 preparing 或 running | 镜头已可用，成片仍在准备／合成 |
| `composition={status:blocked,reason:media_incomplete}`，error 为 `FILM_MEDIA_INCOMPLETE` | 有镜头失败或不可用，保留成功片段，不输出不完整成片 |
| `composition.status=failed` | 展示顶层 error 或嵌套 asset_error／job.error；保留镜头，不自动重试 |
| `status=completed` 且 `composition.asset_available=true` | 成片可用；从 composition 读取最终 asset_id、result_node_id 和 actual_duration_ms |

节点 execution 还返回 `asset_available`、`asset_error` 和 `result_status=available|pending|unavailable`。`status=succeeded` 只是任务历史；输出记录、类型、文件路径、可读性和文件 SHA-256 均校验通过才是可用产物。文件缺失返回 `OUTPUT_ASSET_UNAVAILABLE`，内容变更返回 `OUTPUT_ASSET_CHANGED`；错误附 asset_id／reason，不暴露本地路径。SHA 检查流式读取实际字节，同尺寸替换也会被发现。生成动作和成片动作均按可用产物聚合，读取不会改写任务历史、补文件或触发重新生成。

`requires_user_action` 是展示提示，服务端确认时仍重新检查版本、引用、有效期和预算。生成方案中的节点被修改后，即使 GET 尚显示 proposed，确认也会拒绝失效方案。前端确认前应展示冻结节点、模型、规格、引用和费用，不额外要求用户重复点击“生成脚本”。

## 7. 请求恢复与失败

相同对话请求号且 payload 相同：已完成／明确失败直接回放原响应，不增加模型调用；内容、会话、选择或期望修订改变则 `IDEMPOTENCY_CONFLICT`。受理中同请求返回 `DIRECTOR_REQUEST_PENDING`，不启动第二轮模型。

回执示意：

```json
{
  "client_request_id": "conversation-unique-id",
  "status": "pending",
  "turn_id": null,
  "error_code": null,
  "response": null,
  "flow_version": 2,
  "artifacts": [{"type":"script","node_id":"script","target_id":"scr_example","target_version":1,"saved":true}],
  "actions": [{"action_id":"dact_example","kind":"confirm_script","status":"proposed","requires_user_action":true}],
  "operations": [],
  "may_still_be_running": true
}
```

示例省略 operations 明细。即便最终 turn 写入失败，已提交工具产物和动作仍可读；pending 不等于全部失败，也不能据此把原对话标为完成。GET 不恢复执行、不补写节点、不重报付费任务。前端应保留输入与请求号，核对产物后再决定新动作；已存在可用确认动作时，不需要重写脚本。

服务启动时，`director_recovery` 仅处理新流程 `dreq2_` 的 pending 请求，并且必须有执行 owner 已结束的明确证据：原 PID 不存在，或 PID 对应的启动时间戳已变化。时间戳通过 `ps -p <pid> -o lstart=` 在 `TZ=UTC`、`LC_ALL=C` 下读取，带 `utc-lstart-v1:` 版本前缀；只有同版本时间戳可用于判断 PID 复用。存活 owner、权限不足／无法判断 owner、缺少可靠 owner 的请求和旧流程请求均不会被新服务抢占，旧格式时间戳也不用于不可靠的差异判断。请求存续时间本身不是回收条件。

明确中断的请求在一个事务中改为 `request_status=failed` 并保存 `DIRECTOR_REQUEST_INTERRUPTED` 回执：已有产物或动作时 outcome 为 partial，否则为 failed；保留工具产物、actions、已有媒体任务和原始用户消息，并带 `recovered_after_restart=true`、`usage.has_unknown_cost=true`。缺少原消息的旧上下文不补造用户发言，未知费用不记为零。该恢复不调用模型、不重新生成、不重试合成；只解除已结束请求自身的 pending 锁，其他运行任务仍受项目删除保护。已有可用动作继续按其真实状态供用户核对和确认。

常见业务错误：

| 错误 | 处理 |
| --- | --- |
| `WORKFLOW_REVISION_CONFLICT`／`CANVAS_REVISION_CONFLICT`／`SCRIPT_VERSION_CONFLICT` | 刷新内容，保留用户草稿，重新核对当前版本 |
| `PROJECT_SESSION_MISMATCH`／`CANVAS_NODE_NOT_FOUND` | 更正项目／会话／选择，不继续使用旧选择调用模型 |
| `DIRECTOR_ACTION_EXPIRED`／`DIRECTOR_ACTION_STALE` | 不提交旧动作；显式新请求为当前内容重新准备 |
| `DIRECTOR_ACTION_CONFLICT`／`IDEMPOTENCY_CONFLICT` | 读取原回执，不自动换请求号绕过冲突 |
| `DIRECTOR_REQUEST_PENDING` | 继续只读查回执，不启动第二次调用 |
| `DIRECTOR_REQUEST_INTERRUPTED` | 原执行 owner 已结束；读取保留产物／动作并核对，原请求回放失败回执，不自动重新发送 |
| `FILM_MEDIA_INCOMPLETE`／`OUTPUT_ASSET_UNAVAILABLE`／`OUTPUT_ASSET_CHANGED` | 核对具体镜头或文件；成功且可用的片段保留，不自动补生成或拼接残缺成片 |
| `DIRECTOR_NO_ACTION` | 本轮没有完成创作，不显示生成成功 |
| 模型能力／引用／预算错误 | 显示实际原因，保留已保存节点和旧成功素材，调整后重新报价 |
