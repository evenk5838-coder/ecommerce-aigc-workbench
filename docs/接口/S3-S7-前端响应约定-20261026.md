日期：2026-10-26。范围：`frontend/src/creative/production-types.ts`、`production-api.ts`、`production-guards.ts` 当前客户端实际接受的请求与响应。

**这是前端接入补充，不覆盖 Pi 的正式接口契约，不代表这些接口已经上线或完成真实生成验收。** 路由未提供时界面显示不可用；不会用空列表、假成功或模拟素材补齐。若后端需要改变 shape，请同步正式契约并联合调整客户端测试。

本轮客户端离线检查：2 个测试文件、49 项通过；另有 ESLint 和 TypeScript 检查。证据在 `docs/evidence/S3-S7-Codex-20261026/production-client-checks.json`。这些检查不证明后端已实现，不含真实模型、付费请求或业务数据库写入。

## 1. 公共语义

- 以下路径均以 `/api` 为前缀。JSON 成功体不包额外的 `data` 层。
- ID 为非空字符串。`version`、`revision`、`seq`、`duration_s` 为正的安全整数；数量允许 0。新时长请求不得静默取整或补成默认 5 秒。
- 所有报价为服务端返回的有限、非负数值。前端只加总与核验，不计算模型单价；估算不是供应商账单。
- `created_at`、`approved_at`、`expires_at` 使用 Unix 秒。`actual_duration_ms` 单位是毫秒，存在时须为有限正数；缺失或 null 显示待探测，绝不以计划时长替代。
- 下方 TypeScript 中 `?` 表示客户端允许字段缺失；不意味着对应历史/功能已实现。可空字段按类型显式标注。
- 错误格式采用 `{ "error": { "code": "...", "message": "...", "detail": {} } }`，保留服务端明确错误码。
- 所有写请求都只在用户主动操作后发送。客户端不会自动重发。写入返回无法解析、5xx、断网、发送后中止或超时均按 `CREATIVE_RESULT_UNKNOWN` 保留核对保护。
- 裸 404、405、501 显示 `PRODUCTION_UNAVAILABLE`。有业务错误码的 404 保留业务码，不冒充接口未上线。读取失败保留旧数据并显示错误，不把旧数据宣称为最新。
- 默认等待上限 25 秒；停止等待不等于取消后端任务。GET 文件链接不创建任务。

## 2. 镜头、分镜与历史

公共对象：

```ts
type Storyboard = {
  storyboard_id: string; shot_id: string; version: number; status: string;
  task_id?: string | null; asset_id?: string | null;
  reject_reason?: string | null; created_at?: number | null;
};
type ShotTake = {
  take_id: string; status: string; shot_id?: string;
  task_id?: string | null; asset_id?: string | null;
  actual_duration_ms?: number | null; cost_cny?: number | null;
  created_at?: number | null;
};
type Shot = {
  shot_id: string; project_id: string; revision: number; seq: number;
  duration_s: number; description: string;
  script_id?: string; prompt?: string; motion?: string;
  input_asset_id?: string | null; model_id?: string; status?: string;
  approved_at?: number | null;
  storyboards?: Storyboard[]; takes?: ShotTake[];
};
type ShotInput = {
  seq: number; duration_s: number; description: string;
  motion?: string; prompt?: string;
  input_asset_id?: string | null; model_id?: string;
};
```

| 方法及路由 | 请求 | 当前客户端所需成功响应 |
| --- | --- | --- |
| `GET /projects/{id}/shots` | 无 | `{items: Shot[]}`；每镜 project_id 必须匹配；shot_id 与 seq 不重复 |
| `POST /projects/{id}/shots` | `{script_id, shots: ShotInput[]}` | `{project_id, shots: Shot[]}`；返回本次新建镜头，数量与提交一致，ID 唯一 |
| `PATCH /shots/{shot_id}` | `{expected_revision, ...Partial<ShotInput>}` | 完整 `Shot`；shot_id 与 URL 一致 |
| `DELETE /shots/{shot_id}` | 无 | `{shot_id, deleted: true}`；不接受空 204 作为完整回执 |
| `POST /projects/{id}/shots/reorder` | `{order: string[]}`，完整、不重复镜头顺序 | `{project_id, order: string[]}`；顺序与请求完全一致 |
| `POST /shots/{shot_id}/storyboard` | `{model_id, size, prompt, input_asset_id: string|null}` | `{shot_id, storyboard_id, version, task_id, estimated_cost_cny}` |
| `POST /storyboards/{id}/approve` | `{}` | `{storyboard_id, version, status: 'approved', shot_id?, reject_reason?}` |
| `POST /storyboards/{id}/reject` | `{reason: string}`，非空 | `{storyboard_id, version, status: 'rejected', shot_id?, reject_reason?}` |

需要 Pi 补齐/确认：正式契约原先没有完整列出 GET 镜头列表及镜头 CRUD 回执。前端需要 `revision` 做乐观并发控制，需要读取真实 `storyboards`、`takes` 历史来恢复审核和旧片段选择；不能只给最新图片。若历史暂未提供，前端只显示已收到的记录，不声称完整历史。

镜头 PATCH 冲突应返回 409，不能静默覆盖。分镜审核采用正式增量契约中的 `/storyboards/{id}/approve|reject`，不使用技术方案里另一个旧路径。

分镜生成前，界面先调用已有免费的 `POST /tasks/estimate`，以同一 model_id、size、prompt、input_asset_id 估价；`params.generation_mode` 由是否有参考图明确为图生图/文生图。用户确认费用之后才调用 storyboard 创建接口；读取报价不应触发模型。

## 3. 整组报价、确认与提交

### 报价

`POST /projects/{id}/scope`：

```ts
type ScopeInput = {
  mode: 'full' | 'clips';
  shot_ids: string[]; // 非空、唯一，顺序有意义
  specs: {model_id: string; ratio: string; resolution: string};
  overrides?: Record<string, {duration_s: number}>;
};
type ScopeQuote = {
  scope_id: string; project_id?: string; mode: 'full' | 'clips';
  shots: {shot_id: string; duration_s: number; estimate_cny: number}[];
  total_estimate_cny: number; planned_film_duration_s: number;
  scope_hash: string; expires_at: number;
  side_effects: {tasks_created: 0; model_called: false};
  submittable?: boolean; blocked_reasons?: string[];
};
```

前端严格检查：

1. mode、镜头数量、shot_id 顺序与请求一致，不允许只返回部分成功报价。
2. 每镜 duration_s 是正整数；有 overrides 时必须与明确覆盖值一致。overrides 只能涉及选中镜头，且只含 duration_s。
3. 逐镜金额与合计相差不超过 `0.000001`；计划总时长严格等于逐镜时长之和。
4. scope_hash 为 `sha256:` 加 64 位十六进制；不能返回文档占位值 `sha256:…`。expires_at 必须尚未过期。
5. side_effects 必须明确为 0/false；submittable=false 或非空 blocked_reasons 阻断确认。
6. 若返回 project_id，必须属于当前项目。

服务端仍负责冻结 description、prompt、参考素材、已审核分镜版本、模型、比例、清晰度、时长和相关版本；变化后拒绝旧 scope。前端哈希格式核验不替代服务端真实快照校验。

### 确认

`POST /scopes/{scope_id}/confirm` 请求 `{confirm: true}`，响应：

```ts
type ScopeApproval = {
  scope_id: string; approved: true; expires_in_s: number; max_uses: 1;
  expires_at?: number; scope_hash?: string;
};
```

只能由明确界面点击触发。客户端将回执绑定原始 quote 对象、scope_id、scope_hash；期限取报价期限、回执期限与本次确认请求开始时刻加 expires_in_s 的最早值。回执若包含 scope_hash，必须与报价一致。不得把 LLM 工具调用当成用户确认。

### 提交

`POST /projects/{id}/generate` **只发送** `{scope_id}`，响应：

```ts
type ScopeSubmission = {
  batch_id: string; mode: 'full' | 'clips';
  tasks: {shot_id: string; task_id: string; take_id?: string}[];
  auto_film: boolean; sequential: true;
  scope_id?: string; idempotent_replay?: boolean;
};
```

必须提供完整且有序的 shot→task 映射，task_id 唯一。`auto_film` 必须与 full/clips 相符，`sequential` 必须明确为 true。若返回 scope_id，必须与已确认报价一致。

服务端需按正式契约保证：消费 scope、创建 batch/tasks/takes 与提交回执在同一事务；重复 scope 返回原 batch；旧任务始终使用冻结输入；权限、EOS、规格、预算、确认失效均在服务端再次检查。前端对象绑定不构成服务端授权。

失败镜重试：仅对用户明确选择、当前 status 为 failed 的镜头重新报价、确认、提交；没有自动重试，也不带上成功镜头。

## 4. 项目状态与成片

`GET /projects/{id}/status` 必须返回如下顶层字段；尚无内容时使用 null 或空数组，不能省略 mode/batch/film：

```ts
type ShotStatus = {
  shot_id: string; status: string;
  take_id?: string | null; task_id?: string | null; asset_id?: string | null;
  actual_duration_ms?: number | null;
  error_code?: string | null; error_message?: string | null;
  takes?: ShotTake[]; storyboards?: Storyboard[];
};
type Film = {
  film_id: string; status: string;
  project_id?: string; version?: number;
  planned_duration_s?: number | null; actual_duration_ms?: number | null;
  items?: {shot_id: string; take_id: string; actual_duration_ms?: number | null}[];
  partial?: boolean; missing_shot_ids?: string[]; asset_id?: string | null;
  error_code?: string | null; error_message?: string | null;
};
type ProductionStatus = {
  project_id: string; mode: 'full' | 'clips' | null;
  shots: ShotStatus[];
  batch: {batch_id: string; queued: number; running: number;
          succeeded: number; failed: number} | null;
  film: Film | null; films?: Film[];
};
```

| 方法及路由 | 请求 | 当前客户端所需成功响应 |
| --- | --- | --- |
| `POST /projects/{id}/films` | `{take_ids: string[], confirm_partial: boolean}`，take_ids 非空且唯一 | `{film_id, version, status, partial?, missing_shot_ids?}` |
| `GET /projects/{id}/films` | 无 | `{items: Film[]}`，用于历史列表 |
| `GET /films/{film_id}` | 无 | `Film`，film_id 与 URL 一致 |
| `GET /films/{film_id}/file` | 无 | 可播放/下载的真实视频文件，不返回 JSON 代替文件 |

`confirm_partial=false` 时服务端不得返回 partial=true；缺镜应明确 409。允许部分合成必须由用户额外确认并标注缺镜。纯拼接不裁剪、不重新生成成功片段。

需要 Pi 补齐/确认：项目 film 历史 GET 原契约未明确列出；只有 status.film 不能声称完整历史。Film.version、partial、missing_shot_ids、逐片段实际时长应提供，缺失时界面只显示未知，不补造。

状态轮询仅在页面可见且有已知活动任务时进行。未提供接口或读取失败会停止对应循环，等待显式重新读取；状态读取不会触发生成。

## 5. 结构模板

```ts
type StructureShot = {
  seq: number; role: string; duration_s: number; motion: string; rhythm: string;
};
type StructureTemplateSummary = {
  template_id: string; name: string; latest_version: number; status?: string;
};
type StructureTemplate = {
  template_id: string; name: string; version: number; snapshot: StructureShot[];
};
```

| 方法及路由 | 请求 | 当前客户端所需成功响应 |
| --- | --- | --- |
| `GET /structure-templates` | 无 | `{items: StructureTemplateSummary[]}` |
| `POST /structure-templates` | `{name, snapshot: StructureShot[]}` | `{template_id, version}` |
| `GET /structure-templates/{id}?version=N` | 明确版本 | `StructureTemplate`；返回 id 和 version 必须与请求一致 |
| `POST /projects/{id}/apply-structure` | `{template_id, version}` | `{project_id, created_shots, requires: string[], model_revalidation: {ok: boolean, notes: string[]}}` |

snapshot 非空，seq 从 1 连续排列；仅允许 seq/role/duration_s/motion/rhythm 五个键。不能包含商品名称、卖点、描述、提示词、参考素材、审核/批准等事实字段。role 非空；运镜与节奏可为空字符串。

需要 Pi 补齐/确认：列表 `items` 包装及详情 name/version/snapshot。套用固定版本生成镜头骨架，不沿用旧素材、旧审核或旧报价；商品事实重填、模型与时长重校验。requires/model_revalidation 是实际服务端结果，前端不会因为接口返回 200 就自动记为可生成。

前端并行评审注意：模板套用进行中或结果未知，应阻断同项目旧制作提交；成功后刷新项目、镜头和确认状态。脚本与镜头确认须绑定当前版本，历史 confirmed_at 不代表当前 brief/结构已确认。这些约束仍需前后端联合验收。

## 6. 导出与 S7 边界

`POST /projects/{id}/export` 请求：

```ts
{include: ('film' | 'clips' | 'storyboards' | 'manifest')[]}
```

include 非空、不重复。当前客户端接同步准备好的响应：

```ts
{export_id: string; status: 'ready'; asset_id: string; file_name: string}
```

文件从已有 `/api/assets/{asset_id}/file` 下载。导出已有文件不重新生成；若后端改为异步 export，应先补明确状态查询接口与契约，再调整客户端，不能用 status=ready 掩盖未完成打包。

S7 节点画布展示上述真实项目/镜头/状态，布局保存在浏览器。客户端没有另造一套生成执行器；画布节点也不能跳过需求、脚本、分镜与费用的主动确认。
