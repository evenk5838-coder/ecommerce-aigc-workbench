# 对话导演与自由画布：后端交接指令

日期：2026-10-26。静态核对主仓 HEAD：`ee7c790`。本文是本轮增量设计和开发交接，**不是新增接口已完成的声明**。没有调用真实模型、启动 worker 或写业务数据库。

## 1. 本轮确认的产品体验

- 快捷工作台保留四个明确入口：文生图、图生图、文生视频、图生视频；助手只在用户需要时润色提示词。
- 导演台用真实对话引导：用户描述需求 → Agent 澄清或给方案 → 用户确认脚本与镜头计划 → 生成分镜图并确认 → 一键生成全部视频。
- 视频交付保留两种平级选择：独立镜头片段、直接得到合成成片。成片模式复用现有整组任务和合成机制。
- AI 产物自动保存为**未确认草案**；用户主要负责选择、修改和确认，不要求用户复制聊天内容、手工拼镜头或再点一次“保存”。
- 首屏只展示当前步骤和必要操作；完成后可回看历史。流程位置、可操作动作和确认是否有效由后端真实状态决定。
- 自由画布中的独立节点应分别保存自身提示词、素材、模型和规格；不能依赖一个全局表单或仅浏览器缓存来冒充项目持久化。

三个动作必须分开：**自动保存草案 ≠ 用户确认内容 ≠ 用户授权付费生成**。对话里写“确认了”或模型返回 `confirm=true` 都不能代替真实确认请求。

## 3. 现在可接入的准确契约

### 3.1 现有 chat

**已实现**：`POST /api/assistant/chat`，非流式。

```json
{
  "session_id": "asst_existing_optional",
  "project_id": "prj_existing",
  "message": "我想为这款白色瓶装商品做一条简洁展示视频",
  "intent": "auto",
  "context": {"selected_asset_id": "asset_user_selected", "kind": "video"}
}
```

`session_id/project_id/intent/brief/context` 可省略；`message` 必填。`intent` 仅允许 `auto/generate/optimize_only`。若有 `brief`，会写助手专用 brief。

实际返回字段：`session_id`、`reply`、`reply_type`、`options`、`optimized_prompt`、`explanation`、`missing_fields`、`brief`、`quote`、`manual_params`、`submit_payload`、`recommended_templates`、`structured_ok`、`degraded`、`refusal`、`tool_calls`、`awaiting_facts`、`intent`、`session`、`provider`、`note`。

`reply_type` 当前集合：`optimize_result/clarify/template_recommendation/quote_ready/awaiting_facts/refusal/message`。**没有脚本 proposal 字段**。返回 `brief` 是助手 brief，不能直接等同项目事实或脚本草案。

刷新恢复：`GET /api/assistant/session?project_id=...` 返回 `project_id/session/history/brief`。当前 history 是最近消息窗口（默认 8 条、4000 字符预算），不是完整项目历史。完整回看需新增分页读取，不能只依赖这段 Memory。

当前 `ensure_session` 会在传入另一项目时直接改绑 session。前端临时必须每项目分开 session；新导演契约应拒绝跨项目复用，不能让项目 A 的上下文、方案和批准流入项目 B。

### 3.2 现有采用草案接口

**已实现**：`POST /api/projects/{project_id}/adopt-draft`。

```json
{"kind":"script","content":{"summary":"已有可信结构化草案","shots":[{"seq":1,"hint":"商品整体展示"}]},"base_version":0}
```

请求字段：`kind: "brief" | "script"`、`content: object`、可选 `base_version`。

script 返回：

```json
{"kind":"script","script_id":"scr_actual","version":1,"content":{"summary":"已有可信结构化草案","shots":[{"seq":1,"hint":"商品整体展示"}]} ,"llm_called":false}
```

它只新增未确认脚本版本，内部 source 为 assistant；`base_version` 校验项目当前最新脚本版本，不一致返回 `SCRIPT_VERSION_CONFLICT`。内容目前只要求是对象，不能据接口接受成功推断脚本结构有效。

brief 的 `content` 只允许：`subject/quantity/selling_points/forbidden_elements/target_platform/target_duration_s/style/notes`。返回：

```json
{"kind":"brief","project_id":"prj_actual","brief":{"subject":"白色瓶装商品"},"stale":[],"llm_called":false}
```

采用 brief 会合并项目事实，内容变化会使下游确认失效。当前助手 brief 的 `key_selling_points/audience/keep_features/spec_preference/assumptions` 等字段不能原样传入。

**适用边界**：仅用于已取得可信、结构化、经用户选择的草案。当前 chat 不提供此类脚本对象，前端不能自行从 `reply` 拆分句子、推断镜头数再拼 `content`。该 POST 也没有业务请求幂等键，响应丢失后不可自动重发新增版本。

### 3.3 现阶段安全的最小前端接法

可以提供“项目建议/澄清聊天”，同时保留 `POST /api/projects/{id}/scripts` 的明确生成按钮。该接口直接保存 AI 脚本，返回真实 `script_id/version/content` 后再展示确认按钮。

不能把现有聊天包装成已实现的“对话导演自动产物链”。在新契约就绪前，自动采用聊天脚本/自动规划镜头的入口应不可执行；不能用模拟回复补齐。也不能先 chat 生成一遍、再自动调用 scripts 生成第二遍来假装保存同一个草案。

## 4. 最小后端增量

### D1：项目范围的导演对话编排

复用现有 DeepSeek provider、工具协议、用量记录和业务服务，增加薄的导演编排层，不重新实现生成引擎。

建议增加项目专用导演 chat 端点（见下一节，**当前未实现**），与快捷润色会话分开。所有工具的 project/session 来源由服务端绑定，不由模型自由传参切换。

最小工具能力：

1. 读取当前项目真实 brief、脚本、镜头及 director readiness。
2. 保存需求提案、脚本草案、镜头计划草案，并返回真实 ID/版本/保存结果。
3. 查询模型能力、素材元信息和现有任务。
4. 计算分镜或视频方案报价，但不确认、不提交。

不向模型暴露用户确认、付款、提交或额度修改工具。当前 `get_brief/save_brief` 会使用模型传入的 project_id；新导演工具必须绑定当前项目并校验引用对象归属。

提示词中现有“采用草案后才保存”的规则需调整为：**草案自动保存，确认须用户操作**。保存失败必须明确 `not_saved`，不能仅凭模型文本声称保存成功。

### D2：自动保存产物与用户确认

- 脚本可直接复用 `script_versions` 自动追加未确认版本；返回真实脚本引用，不新增一套平行脚本存储。
- 需求提案与镜头计划必须有可恢复的结构化草案；可复用合适的已有存储，但要给出 schema/version/归属，不能只塞进聊天自然语言。
- 先保存提案；用户确认需求时才合并入项目事实；用户确认镜头数量与描述后再应用计划。不得将 Agent 的猜测写成用户事实。
- 镜头计划必须明确绑定 `script_id + version`；采用时校验当前脚本确认有效且引用仍是当前版本，禁止用旧脚本暗中建新镜头。
- 用户调整镜头数量后，Agent 产生新草案版本；不能静默替换已确认的镜头集合。
- 已有脚本确认、分镜审核、scope 确认/提交继续复用。不要让前端从消息字符串推断下一阶段。

### D3：独立节点的参数与布局持久化

- 服务端保存节点 ID、所属项目、节点类型、业务引用（脚本/镜头/素材/任务）、位置、参数版本、输入素材引用、提示词、模型与能力相关规格。
- 四模式使用已有 `generation_mode`；文生模式不夹带旧参考图，图生模式必须校验真实图片输入。比例/时长/清晰度继续由模型能力决定。
- 每个节点分别保存配置；切换节点、刷新、重开项目后能恢复。已有 tasks/takes 的执行快照不能代替“下一次生成”的编辑配置。
- 保存配置与生成任务分开；拖动、连线、缩放、改文字都不自动调用生成模型。
- 布局 revision 与创作输入 revision 区分：移动节点不使报价失效；修改模型/素材/提示词/规格则使受影响的确认与报价失效。
- 连线只表达已支持的输入引用与依赖；拒绝非法类型/跨项目引用/循环依赖。此轮不扩展任意代码执行、无限自治 Agent 或音频等未约定能力。
- 参数编辑不得覆盖历史任务、费用或产物；当前配置与不可变执行快照同时保留。

### D4：幂等、恢复和预算

- 为导演消息建立 `client_request_id` 和持久化回执。同一个键同一个请求返回同一结果；键相同而内容不同明确冲突。双击/断线重试不重复调用 LLM、不重复新增脚本/镜头。
- 外部模型调用与数据库事务不能假装原子提交：需要 pending/completed/failed/unknown 执行记录；未知状态先查回执，不能默认再次付费生成。
- 草案采用带 `expected_version`；读取过期版本时返回冲突，前端刷新恢复，不覆盖新结果。
- 现有 scope 的幂等整组提交继续复用；分镜生成等新增编排入口也要绑定真实批准及请求回执。
- 当前 `MAX_SESSION_COST` 检查只出现在 quote 路径；chat 的 LLM 前置保护主要是轮次/工具轮数。导演模式需在**每次 LLM 请求前**执行 Token/费用预算检查，返回可解释限额状态。不能仅靠提示词“不要闲聊”。
- 保留业务范围、内容限制、轮数、Token、超时上限；停止后保留产物，用户可以直接工作。不要自动新建会话绕过限额。
- 图片/视频生成与 LLM 对话费用分开记录、可汇总。测试不自动沿用旧预算；已有批准只按其明确用例与上限执行。

## 5. 建议的新契约（以下全部未实现，待后端落地后前端再调用）

端点命名是建议；后端可在等价语义下调整，但必须先给确定 schema 和真实响应样例。以下示例 ID/费用状态是说明性占位，不是实测数据。

| 建议端点 | 用途 |
| --- | --- |
| `POST /api/projects/{id}/director/chat` | 项目范围对话，返回已保存草案引用与服务端动作 |
| `GET /api/projects/{id}/director/messages?cursor=...` | 分页恢复完整对话；LLM Memory 仍用有限窗口 |

## 6. 验收与前后端分工

**后端先完成**：项目隔离的导演对话、结构化提案自动保存、确认边界、消息/操作回执、节点配置与版本、真实 readiness。给出准确响应 fixture 后，前端即可并行消费。

**前端负责**：对话输入与选项卡片、当前步骤单一主操作、真实产物预览/确认、自由画布布局和节点编辑、深浅主题、错误/过期/恢复提示。前端不自行编脚本、不推断确认、不自己计价、不创建假任务。

最低免费验收：

1. 对话只澄清时没有脚本/图片/视频任务；有效脚本草案保存后返回真实 ID，刷新仍可取回。
2. LLM 返回畸形结构、假 ID、伪造确认、越权项目工具参数时，失败或降级；没有假成功。
3. 重发同一请求、双击、ACK 丢失后恢复，不重复扣用量、不重复新增产物；相同幂等键不同内容拒绝。
4. 项目 A session 不能改绑为 B；素材/脚本/镜头引用必须属于合法范围；当前无完整多租户鉴权时不得宣称公网安全。
5. 自动保存不自动确认；没有用户批准不能创建图片/视频任务；“直接成片”模式在批准范围内继续复用现有合成链。
6. 改 brief/脚本/镜头或节点生成配置后，旧确认/报价在服务端失效；仅移动节点不失效。旧产物仍可回看。
7. 多个独立节点不同参数，刷新/重开/切换项目后正确恢复；未保存状态明确；文生节点不带隐藏参考图。
8. 历史全部可分页回看；不会因只保留最近 8 条消息丢失已确认事实或脚本；模型上下文从真实项目状态重建。
9. LLM 预算耗尽、超时或不可用时保留已保存产物，不自动续会话、重试、重生成；快捷工作台不受阻。
10. 四模式和既有 B0–B6 回归通过；费用估算与真实账单、替身测试与真实 LLM 端到端分开记录。

真实验证需覆盖一条完整对话：描述商品 → 澄清 → 自动保存脚本 → 用户确认 → 镜头计划确认 → 分镜报价/生成/审核 → clips 或 full → 回看导出。先用隔离测试和替身验证状态，再在用户明确批准的预算内测真实 LLM/图片/视频；不能把替身结果叫真实导演能力。
