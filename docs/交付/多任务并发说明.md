# 多任务并发说明（v0.3.1 · 本地工作台 + 云端推理；含参考图隔离）

> 2026-10-22｜形态：本地工作台 + 火山方舟云端推理｜实现：`backend/app/{worker,cloud_tasks,providers_ark,db}.py`
> 本文只写**已实现且被验证**的行为；未实现能力明确标注。每条关键结论附真实证据。

## 1. 一句话结论

支持**多任务提交与持久化排队**，当前为**单worker执行**。2026-10-22产品化盘点核对：`worker.start()`仅创建一个工作线程，`APP_CONCURRENCY`配置值用于状态展示，不能仅改配置就实现多worker并发。
云端形态下本机不承担模型推理。实际增加并发需补调度、限流、费用预占与幂等验证，并核对账号额度；目前没有多并发吞吐实测证据。

## 2. 队列模型

```
提交 → tasks(status=queued, params 快照) → SQLite
     → worker 原子领取（BEGIN IMMEDIATE）
     → 图片：running → 云端同步调用 → 落盘 → succeeded
     → 视频：remote_queued(落库 remote_task_id) → remote_running → 轮询 → 下载 → succeeded
```

- **参数快照**：提交即冻结，之后改画布/草稿不影响已提交任务。
- **顺序**：FIFO；`priority` 字段预留未启用。
- **批量**：`POST /api/batches` → N 个独立任务（同 batch_id），独立状态、独立重试。
  **实测**：`batch_9b9bd7497e3a4eb8964a` 3 个尺寸任务顺序执行，13.3s / 14.7s / 23.4s，全部成功（`docs/evidence/阶段3/cloud-batch-3sizes.json`）。

## 3. 状态机（当前形态）

```
queued → running → succeeded                    （图片）
queued → remote_queued → remote_running → succeeded   （视频）
          │                  ├→ cancel_requested → canceled
          │                  └→ failed
          └→ canceled（排队中取消）
重启：带 remote_task_id 的非终态任务 → queued(stage=resume_poll) → 续查
本机执行中崩溃：running → interrupted（不自动重跑）
```

## 4. 四种「停止」语义（严格区分）

| 语义 | 实现 | 真实证据 | 边界 |
| --- | --- | --- | --- |
| **本地排队取消** | 直接移除，不发起云端请求 | 本地阶段实测（`docs/evidence/阶段2/flow-tests.json` 案例 B） | 立即、免费 |
| **云端排队中取消** | 先向云端问真实状态 → 若 queued 则 `DELETE /tasks/{id}` | 未拿到成功样本：云端排队到 running <1s，两次实测都已是 running | 官方仅支持取消排队中 |
| **云端运行中取消** | 停止本地轮询与下载 → `cancel_requested → canceled`，`cloud_canceled:false` | 实测响应：`{"result":"cancel_requested","phase":"cloud_running","cloud_canceled":false,"message":"…云端任务可能仍在执行并计费"}`；官方 DELETE 实测返回 **409 Cannot delete task because it is currently running** | **云端继续执行并计费**，不夸大 |
| **从头重试 / 断点续跑** | 重试 = 新建任务（可覆盖参数），原任务保留；**断点续跑未实现** | 重试实测通过 | 重试会再次计费 |

## 5. 失败处理与重试策略

| 错误类型 | 处理 | 自动重试 |
| --- | --- | --- |
| `PROVIDER_RATE_LIMITED`(429) / `PROVIDER_UNAVAILABLE`(5xx、网络) | 退避重试（轮询场景内建 3→5→10→20→30s） | 是（有限） |
| `AUTH_MISSING` / `AUTH_FAILED` | 直接失败，提示检查 `.env` | 否 |
| `MODEL_NOT_OPENED` | 直接失败，提示控制台开通 | 否 |
| `CONTENT_REJECTED` | 直接失败，提示换提示词 | 否 |
| `CREATE_RESULT_UNKNOWN` | **不自动重发**，保留 `safety_identifier=本地 task_id` 供对账 | **否**（防重复计费） |
| `BUDGET_NOT_APPROVED` / `BUDGET_EXCEEDED` | 拒绝，不发起请求 | 否 |
| `DOWNLOAD_FAILED` | 仅重试下载，不重新生成 | 是 |

每次尝试写 `task_attempts`（时间、结果、错误码、耗时），失败原因保留可读信息。

## 6. 重启恢复（真实云端任务实测）

方法：视频任务创建成功（`remote_task_id=cgt-20261022163400-crwcm` 已落库）→ `kill -9` 后端 → 重启。

| 观察 | 结果 |
| --- | --- |
| 恢复摘要 | `GET /api/health` → `recovery:{interrupted:0, queued:1}` |
| 任务状态 | 重启后立即回到 `running` 并继续轮询 |
| 是否重建云端任务 | **否**，`remote_task_id` 与重启前完全一致 |
| 最终结果 | `succeeded`，704×1248，36.8s，历史费用记录¥1.6335（旧15元/百万token估算，非账单） |
| 是否重复计费 | 否（云端只有一个任务） |

> 本机推理阶段（历史）另有一组证据：强杀后 `interrupted=1`、排队任务续跑成功，见 `docs/evidence/阶段2/restart-recovery.json`。

## 7. 预算与成本闸门（云端形态特有）

```
当天已记估算 = SUM(cost_cny) WHERE finished_at > UTC 当日 0 点
APP_BUDGET_CNY = 0            → BUDGET_NOT_APPROVED（不发起请求，实测拦截）
已记估算 + 本次估算 > 上限    → BUDGET_EXCEEDED
```

- 估算口径：图片按张单价；视频按 `token/秒 × 时长 × 单价`（系数取官方示例，实测后校准）。
- 历史阶段记录：6次成功调用累计估算 **¥5.23**，含旧视频单价口径，不代表当前累计或最终账单。
- 当前只统计已经写入任务的费用估算，没有独立费用预占/结算账本；扩展并发前需补齐。界面“今日”与业务时区还需统一。

## 8. 草稿与「生成时继续编辑」

- 草稿存 SQLite（`drafts` + `draft_versions`），每次保存写快照，不回写历史。
- 任务持参数快照，生成期间保存草稿互不影响（本地阶段已实测：版本 1→2，快照 3 条）。
- 乐观锁：`PATCH` 带过期 `base_version` → `409 DRAFT_VERSION_CONFLICT`。

## 9. 已知缺口

| 缺口 | 影响 | 现状 |
| --- | --- | --- |
| 云端运行中取消 | 只能停止本地等待，云端继续计费 | 官方无接口，UI 已明示 |
| 并发 > 1 | 尚无多worker实现与云端429/吞吐实测 | 当前单worker，不是改配置即可开启 |
| 断点续跑 | 中断只能从头重试 | 不实现 |
| 自动重试上限配置化 | 目前固定有限次 | 可配字段预留 |
| 批量交付包 | 素材库已有选中素材ZIP导出；按批次审核、命名和清单自动交付未实现 | 不将两者混写 |
| `seedance-1-0-pro-fast` 单价 | config已修正为4.20元/百万token，依据2026-10-22核对记录 | 历史15元口径记录保留，均为估算；详见评测报告A4 |
