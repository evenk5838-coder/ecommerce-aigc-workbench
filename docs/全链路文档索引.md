## 4. 文档与证据如何连起来

建议从下一版起采用追踪关系：

`客户问题/任务样例 → 需求编号 → PRD条目 → 页面/接口/数据变更 → 测试用例 → 实测证据 → 发布版本 → 用户反馈`

示例仅示意，尚未立项：

`客户要一次交付多个SKU → REQ-候选-批量生产 → 生产清单PRD → 批次接口/审核页 → 单SKU失败不影响其他SKU用例 → 实际结果与导出清单 → 试点版本 → 人工返工反馈`

维护规则：

- 当前结论置顶，旧结论放历史区并标时间；同一事实不同时写“已完成”和“待实现”。
- 实测记录写清模型、输入、参数、输出、耗时定义、费用口径和人工评价；不公开Key或客户私密素材。
- 研究事实、用户意见、产品假设和待验证事项分别标注。
- 代码、文档、证据各有版本；已有数据库记录与失败样例不为修正文案而篡改。
- 任何“已上线”“已隔离”“已恢复”“已支持并发”的表述，都附对应实际验证；不以配置存在或页面能打开替代。
