## 2. 新增项目删除契约

`DELETE /api/projects/{project_id}`，无请求体。

```json
{
  "project_id": "prj_example",
  "deleted": true,
  "deleted_at": 1793000000.0,
  "already_deleted": false
}
```

- 软删除，只写项目删除标记；素材、任务、脚本、分镜、成片、会话与文件均保留。
- 重复删除返回同一删除时间，`already_deleted: true`。
- 默认项目列表排除已删项目；项目详情、项目内读写入口返回 `410 PROJECT_DELETED`。历史任务和公共素材仍可读取。
- 不存在的项目为 `404 PROJECT_NOT_FOUND`，与已软删项目区分。
- 活动任务、未知任务状态、供应商创建结果未知、产物尚未回写、待自动合成、合成处理中、对话请求处理中均为 `409 PROJECT_BUSY`。不取消任务，不发起重试，不删除输出。
- `PROJECT_BUSY.detail` 可包含 `tasks`、`films`、`requests`、`pending_outputs`、`assembling_batches` 或 `operation_in_progress`；UI 显示简短阻断理由即可。
- 服务层项目锁覆盖调用及保存过程；SQLite 触发器阻断已删项目的过期关联写入，事务整体回滚。未增加恢复按钮或恢复 API。

## 3. 导演消息刷新恢复契约

`GET /api/projects/{project_id}/director/messages` 新增顶层字段：

```json
{
  "project_id": "prj_example",
  "session_id": "asess_example",
  "workflow_revision": 123456789,
  "actions": [
    {
      "type": "confirm_script",
      "target_id": "script_example",
      "target_version": 1,
      "requires_user_action": true
    }
  ],
  "items": [],
  "next_cursor": null,
  "has_more": false
}
```

- `session_id` 可为 null。顶层 `actions` 由当前服务端确认链和有效草案计算；历史 `items[].structured.actions` 只用于回看，不能作为当前操作按钮。
- action 类型为 `confirm_script`、`apply_shot_plan`、`apply_brief`、`quote_generation`；相应携带 target 或 proposal 的 ID/版本；均要求用户显式操作。
- `workflow_revision` 是 JavaScript 安全整数范围内的 opaque 比较值（当前实现最大 52 bit）；不得做加减、排序或推断阶段。POST chat 可携带 `expected_workflow_revision`，不匹配返回 `409 WORKFLOW_REVISION_CONFLICT`。
- 已完成请求按 `client_request_id` 重放原回执，先检查幂等回执、后检查当前版本。失败请求保存 `failed` 状态，同 ID 不重新调用模型，返回 `DIRECTOR_REQUEST_FAILED`；前端先查回执和已保存草案，再由用户决定是否发新请求。
- 新增有限项目历史进入模型上下文（最多最近 8 轮、12000 字符）；项目之间隔离。完整历史仍从 messages 分页读取，同时间戳记录不会漏页。
- 工具续轮也检查预算，累计各轮 token 用量，显式限制输出 token。费用是应用侧估算，不能当供应商账单；超时保留估算用量而非声称零费用。
- 提案应用与幂等回执在同一事务内完成，避免应用成功却无回执导致重复镜头。

## 4. 画布与确认链修复

- 画布 GET 为纯读取，不创建空记录。
- PATCH 全部校验成功后原子保存；后一个节点/连线非法时，前面的节点和确认状态也不落盘。
- 只移动节点保留已有类型、绑定和参数；GET 返回持久化连线。配置变更仍使相关生成确认失效。
- 校验跨项目绑定、素材类型、模型能力与输出规格，不能把不支持的参数保存成“可生成”。
- 同版本确认被上游修改失效后可重新确认；旧失效记录快照写入 `confirmation_events`，避免唯一约束报错且保留历史。
- 自动保存草案不代表用户确认；对话工具不直接确认脚本、不生成图片/视频，仍沿用显式确认与报价流程。
- 最后补充：完全无绑定、无配置的画布展示节点不进入 `workflow_revision` 哈希，新增或移动此类节点不会让下一条对话误报版本冲突。有真实配置或绑定的节点仍进入哈希，变更后旧对话基线继续返回 `409 WORKFLOW_REVISION_CONFLICT`，不会自动吞掉业务冲突。
