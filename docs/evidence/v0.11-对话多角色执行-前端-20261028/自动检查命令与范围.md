# 对话多角色执行前端自动检查

复现命令：

```sh
APP_PYTHON=/private/tmp/ecom-v011-backend-20261027/bin/python bash verify.sh director-workflow-frontend
```

检查按当前项目结构适配 `ai-product-starter-kit` 的五类验证，保留所有旧模式。每次执行以东八区时间与进程号生成新的 `verify-<时间>-<PID>.txt` 及 `run-<时间>-<PID>/`，不覆盖历史执行结果。

| 检查 | 实际范围 |
| --- | --- |
| 1 | 全量 ESLint、TypeScript 严格类型与 Vite 生产构建；输出仅为 `/private/tmp/ecom-v011-frontend-preview/workflow-dist` |
| 2 | 全量前端 Vitest；包含会话 API、恢复、确认卡、引用连线、局部进度、路由及保留回归 |
| 3 | `.env` 忽略及未跟踪检查；生产源码、旧构建与本次 workflow-dist 的文本凭据模式扫描，只输出命中文件名，不读取 `.env` 内容 |
| 4 | 新建标记隔离数据库和独立 HTTP 服务；固定模型回复及 PNG／MP4、真实队列、实际本地 FFmpeg 拼接；分别验证 clips、film 路径及进程重启、防重 |
| 5 | 必要技术文件、`git diff --check`、旧 `frontend/dist` 验证前后 SHA-256 完全一致；本轮前端源码、测试、构建配置、验证入口及已构建 workflow-dist 在验证过程中未变化 |

每轮另存本次 `frontend-input-sha256.json` 和 `workflow-build-sha256.json`，并在验证结束时重新核对。它们只证明该次验证期间所覆盖的前端文件与构建未变；不代表旧服务或其他预览加载了这一构建，也不证明验证结束之后的源代码没有变化。浏览器记录必须另行注明当时访问地址、构建及实际操作。

检查不重启业务服务，不读取业务数据库，不读取 `.env`，不执行付费模型请求；新建临时 HTTP 实例只由验证脚本管理，不能作为浏览器或真实模型验收证据。真实脚本质量、图片／视频质量、真实报价和账单、用户视觉验收、手机真机、最终发布均须独立记录。

此入口的通过结果只表示自动检查通过。后端完整单测已在前批验证，本入口不重复运行全量后端单测。
