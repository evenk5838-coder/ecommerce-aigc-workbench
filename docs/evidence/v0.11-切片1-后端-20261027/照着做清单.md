# 本批查看与后续验收

当前是后端交接，网页仍运行上一版。先查看本目录 `是否表.md`、`verify-输出.txt` 和 `run-…/隔离HTTP响应.json`；JSON 中都是临时测试项目和明确的模型替身，不是用户业务数据或真实模型产物。

可核对结果：

1. `saved.outcome.status` 为 saved，`saved.artifacts` 含真实临时脚本 ID、版本及 `node_id=script`。
2. `canvas.nodes` 同时含自由文本、图片／视频配置、导入素材和脚本节点；`scripts.items` 含正文。
3. `failed.outcome.status` 为 failed，包含实际工具错误，不因请求 HTTP 200 显示“脚本已生成”。成功脚本仍保留。
4. verify 的服务重启项有“首次启动→进程退出→重启→回读一致→进程退出”的实际输出；同请求号回放不追加模型调用。

开发者可复跑：`APP_PYTHON=/private/tmp/ecom-v011-backend-20261027/bin/python bash verify.sh v0.11-backend`。临时环境失效时，以 Python 3.12 新建隔离环境并安装 `backend/requirements-test.txt`。检查需本机随机端口权限，不占用 8100／5184；不要将检查脚本改为真实业务库路径或真实模型。

下一步由用户切换到前端所用模型后继续，接入全工作区画布、可收起对话和自由节点。届时提供真正可点选的页面验收；本批不要求用户在旧网页寻找尚未接入的按钮。真实文本模型验证另核对具体用例及费用范围。
