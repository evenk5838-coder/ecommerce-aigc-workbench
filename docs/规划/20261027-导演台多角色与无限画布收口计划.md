# 导演台多角色与无限画布：后续开发与收口计划

日期：2026-10-27，Asia/Shanghai。性质：按用户最新澄清整理的执行计划；不是新增功能完成声明。

依据：当前 [PRD v0.11](../PRD/PRD.md)、[41 条需求及本批状态](../阶段文档/阶段3-v0.11-切片1前端.md)、用户关于 OiiOii 无限画布、澄清引导及多角色 Agent 的最新说明。继续使用 agent-builder 与 ai-product-starter-kit 工作流程。

## 1. 产品目标与参考范围

**导演台的核心是多角色 Agent 在一个对话里引导用户、澄清必要信息并实际完成创作；无限画布承载结果，也允许用户随时主动干预。** 两部分一同交付，不能只做好画布或只展示角色名称。

- OiiOii 参考用于导演台的无限画布、节点操作与参数面板，以及 Agent 的澄清、确认、下一步引导和工具执行体验。其服务端 Agent 拓扑仍未知，不据此照搬内部架构。
- 保留物料间已确认的 C 版整体 UI 与深浅主题。项目首页、快捷工作台及其他部分继续按本项目需求实现，不复制 OiiOii 的会员、发布、3D、音频或其他扩展产品。
- 用户追加：单个节点选中后也能删除；单节点删除和框选批量删除都能撤销。恢复节点内容、位置、配置、引用和可恢复连线，保留原素材及任务，不重新生成或扣费。
- 延续单一项目对话入口；内部按编剧、导演、摄影师、剪辑师承担专业职责。各职责有明确输入、工具和产出，读取同一项目上下文；先沿用一个主控与专业能力，不为岗位数量引入新框架。
- 原有项目、素材、任务队列、四模式、版本与 ffmpeg 合成能力继续复用。保留 41 条要求，并将本次新增画布操作与简化交互作为补充，不删除历史要求。

## 2. 用户真正经过的流程

| 当前职责 | 用户怎样参与 | 必须产生的结果与下一步 |
| --- | --- | --- |
| 编剧 | 说想法，回答必要问题，提出脚本修改或确认 | 实际脚本保存并出现在画布；导演围绕该脚本提出镜头方案 |
| 导演 | 确认画面方向、参考素材和本次生图范围 | 每个镜头的实际图片、进度与独立节点；引导审核和定向调整 |
| 摄影师 | 讨论动作、运镜、时长和视频规格，确认本次生成 | 使用选定图片版本或模型支持的文本输入，产生逐镜视频 |
| 剪辑师／合成 | 明确使用哪些片段、顺序及交付方式 | 完整视频模式按已明示范围自动合成；独立片段模式先交付片段 |

不固定追问次数。用户信息足够时直接行动，缺少会影响结果的信息时再问；已知信息不重问，同一动作不重复确认。角色以实际工作切换，不能因一条“已完成”的回复就推进。

用户也能从已有脚本、图片或视频开始；按当前目标所需输入判断下一步，不要求重新走无关阶段。关闭聊天仍可手动操作节点，重新打开后 Agent 能读到这些修改。

## 3. 当前可复用基础与缺口

- 已有基础：C 版全工作区画布、可收起对话、项目创建与删除、文本／图片／视频节点配置、上传及引用、脚本保存节点、版本、持久化任务和合成。
- 本批证据：前端 595 项自动测试及隔离浏览器联调；后端上一批 106 项检查。固定 LLM 不替代真实模型验收。
- 当前缺口：手型／选取模式与多选；节点提示词主面板及生成按钮；独立节点到任务／产物的绑定；对话媒体执行工具；完整专业职责交接；局部重做；任意已有视频参与合成；统一真实验收与稳定本地交付。
- 代码关键限制：现有 director_chat 仍限制只写草案，项目 allowed 判断仍存在阶段门槛。两处要改为动作级输入依赖和明确批准，才能实现对话执行与中途开始。

## 4. 开发顺序、分工和交付

不把所有后端写完再一次性铺前端。按下面顺序接通小闭环；实际编码按后端／前端分批，开始前提醒用户切换模型。每个闭环都留下可操作结果及对应证据，真实测试在后续开发中逐步累积。

| 顺序 | 后端工作 | 前端工作 | 本步完成标准 |
| --- | --- | --- | --- |
| 1 共同执行能力 | 明确节点→输入版本→确认范围→任务→产物关联；复用已有生成、报价和队列，补独立节点执行／重做／查询；按动作依赖判断可用性 | 对齐返回状态、引用选择、生成按钮和对话确认的接口 | 同一节点从手动和对话入口执行时使用相同规则；有真实任务与结果绑定；恢复不重复提交 |
| 2 可操作画布与单节点 | 支持单／批量删除及持久化撤销、引用更新、四模式合法参数；已有图片不要求脚本才能做视频 | 手型平移、箭头框选、增减选择、成组移动／删除；单节点选中后删除；工具条撤销及 Ctrl／⌘+Z 恢复误删；文本／图／视频创建；提示词主面板，底栏模型／比例／参数及生成／重生；引用连线；设置随节点缩放 | 新建、编辑、真实生成、移动／缩放、刷新恢复通过；单／批删可撤销且不重复扣费；现有图片能直接转视频 |
| 3 编剧对话闭环 | 为对话提供当前画布和选中节点；用工具实际保存／修改脚本；澄清与执行状态一致；保存成功不依赖再次调用模型宣布 | 统一输入框，移除“讨论想法／生成脚本”模式切换；聊天结果定位脚本节点；编辑后一次确认；下一步引导在对话中出现 | 用户提出明确需求后得到实际脚本；确认后导演接续，不靠隐藏表单或手动换角色 |
| 4 导演与摄影师 | 镜头方案、按范围建节点及生图／生视频；读取选定素材版本；支持目标镜头修改和有限恢复 | 每张图／每条视频独立进度与预览；单节点设置；聊天可指向“第二镜”；批次成功失败分别展示 | 两镜头产物真实可用；只重做第二镜时第一镜和旧成功结果保留；角色沿用已有诉求 |
| 5 剪辑师与交付 | 合成接受明确片段及版本、显式顺序；桥接导入视频；完整／独立片段两种模式；恢复和结果校验 | 调整合成片段顺序，显示计划与实际时长；成片播放、下载；完整模式成功后自动呈现结果 | 从头创作和已有视频中途开始均能得到可播放下载的成片；拖动画布不改变剪辑顺序 |
| 6 整体验收与本地交付 | 检查预算、防重、任务恢复、错误和持久化；在保留业务数据前提下验证启动／重启 | 回归首页、项目管理、快捷四模式、主题、结构模板及既有导出；桌面／窄屏和用户体验验收 | 通过第 6 节清单，提供稳定启动说明、版本归档、实际证据和明确未通过项 |

第 1、2 步共同构成第一批可用结果；第 3 步起，按编剧→导演→摄影师→剪辑师逐个验证真实工作能力。优先跑通一种已开通图片模型和一种视频模型，其他已有模型按能力回归，不为复刻增加新供应商或本地 GPU 部署。

## 5. 全程遵守的交互和执行规则

1. **只用一个对话入口。** 不要求用户选择工作模式、切换 Agent 会话、填写隐藏需求表单或重复提供商品资料。复杂信息可以在对话里一次澄清。
2. **一次确认对应当前范围。** 对话确认和节点生成箭头共用执行服务；保存脚本不扩大为批准媒体费用。展示本次必要规格及费用后执行；重新编辑影响费用或输入时更新相应确认。
3. **一个动作只生成一次。** 用户重复点击、网络重试、刷新和恢复会话应查回原请求／任务；受理未知先核对，不自动新建一笔付费生成。
4. **手动编辑能被 Agent 看见。** 修改节点提示词、参考素材或模型后，Agent 使用实际最新配置；已提交任务继续使用提交时的输入快照。
5. **局部改动范围明确。** 重做指定镜头保留其他成功项与历史产物；上游改变后标记受影响下游，是否重新生成由用户决定，不静默扣费。
6. **停止和删除语义清楚。** 停止等待不冒充取消生成；删除画布节点不等同删除原素材或取消在途任务。单节点选中可删；批量删除与单节点删除采用相同规则，并以一次删除操作为单位撤销，恢复全部对应节点及可恢复关联。撤销保留其他节点后续编辑，存在身份／版本冲突时明确提示，不能用旧快照覆盖新内容。撤销只恢复画布，不新建生成任务；输入框内 Ctrl／⌘+Z 优先撤销文字，避免误触画布撤销。
7. **连线表示实际引用。** 素材关系可视化，与真实生成输入一致；画布坐标不决定片段顺序，不引入通用条件／循环工作流。
8. **沿用当前成片范围。** 合法原生时长、显式顺序、纯拼接；计划与实际时长分开，不借参考报告扩大为复杂时间线裁切、变速、配音、字幕或配乐系统。

## 6. 收口验收清单

| 场景 | 怎样算通过 |
| --- | --- |
| 从一句需求开始 | 编剧澄清必要信息，实际脚本上画布；导演接续分镜；摄影师执行视频；按交付方式得到片段或成片 |
| 用户随时主动调整 | 手型平移、框选多节点、一起移动／删除；节点设置随缩放；正文、参数和引用刷新可恢复 |
| 删除与误删恢复 | 单节点选中删除、框选批删均可用；点撤销或画布 Ctrl／⌘+Z 恢复同次删除的节点、位置、参数和引用；其他新编辑保留，原素材和任务不删除，恢复不重新生成；重开可查回删除记录 |
| 四种生成输入 | 文生图、图生图、文生视频、图生视频入口及模型能力匹配，真实产物可读；不沿用过时强制首帧限制 |
| 定向修改 | 对话说“只改第二镜”，实际只修改／生成目标，第一镜与旧结果仍在 |
| 中途开始 | 外部图片直接生成视频；已有视频直接排序合成，无无关脚本门槛 |
| 重复操作和恢复 | 重复点击、生成中刷新、停止等待、断线／受理未知、服务重启均不造成自动重复扣费，失败可明确恢复 |
| 两种交付 | 完整模式按已明示范围自动合成；独立模式交付逐镜片段；有失败项不伪称完整 |
| 旧功能保留 | 项目创建／删除、失效项目处理、首页滚动、快捷工作台、主题、结构模板保存／查看／套用、原有 PNG／ZIP 等导出通过回归 |
| 最终交付 | 真实媒体可播放下载，稳定本地启动，业务数据保留，代码和文档版本归档，真实费用及待验项清楚 |

真实样例优先复用已生成素材，逐步扩展同一项目。用例与报价先核对已有授权范围；范围内继续执行，新增费用超出授权时再明确说明，不把旧调研积分或 PRD 确认当作无限授权。

不能以测试数量、截图、角色标题或固定模型回复宣布完整收口；整版完成结论必须有真实对话与媒体执行、恢复回归及用户可操作证据。今天的交付目标为可用本地版本，不新增公开部署、会员计费、3D、音频或其他产品体系。
